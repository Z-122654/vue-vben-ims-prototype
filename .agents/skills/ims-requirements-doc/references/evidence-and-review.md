# 证据判定、更新与检查

## 区分要求与事实

为每条关键规则保留依据及确认状态，同时单独记录实现情况。已确认的规则可能尚未实现；已实现的行为也可能尚未确认，两者不能相互替代。

| 标记 | 判定依据 | 文档处理 |
| --- | --- | --- |
| 已确认需求 | 用户明确要求或明确接受的规则，或已确认采用的需求材料 | 写入目标业务规则，注明依据；实现不一致时另列差异 |
| 原型现状 | 当前代码、配置或实际观察到的页面行为 | 写在现状及追溯中；无确认依据时注明目标规则待确认 |
| 待确认建议 | 助手建议、推断、含糊表述、缺少依据或尚未解决的冲突 | 保留建议、影响和问题编号，不写成强制需求或已承诺的验收标准 |
| 演示限制 | 仅为 Mock、演示、临时存储或演示身份服务的约束 | 单独说明用途，正式系统是否沿用需另有依据 |

这些标记用于业务事实，不是文档完成度。草稿中可以存在已确认需求；不要因生成完成就标记整份文档“已确认”。同一事项可以同时记录一个已确认目标和一个不同的原型现状。

### 冲突与缺失

- 用户对某项旧规则作出明确修订时，更新该项并保留变更依据；不要推断未提及的相关规则也已改变。
- 业主文件是需求来源，用户说“参考”或“写得不错”不等于逐项确认其中所有细节。文件与已确认讨论有冲突时并列记录，不能用代码或文件时间自行裁决业务意图。
- “就按你的建议”只确认当时可明确定位的建议。无法定位原建议时说明证据不足，不补造历史。
- 没有默认值、长度限制、权限条件或异常提示依据时，标出未知及影响，不为了表格完整自行设定数值或精确文案。
- 区分“未实现”“未核验”“实现与需求不一致”。仅凭截图不能证明权限、保存或自动时间记录正确；代码分支存在也不能证明运行验收已通过。
- 优先从已有材料和源码解决事实问题。核心流程、权限、数据归属的歧义集中提问，其余问题在草稿中登记，已确定内容照常完成。

## 追溯与更新

每项关键规则至少能追溯到材料章节、可识别的讨论结论或仓库相对路径与符号。记录核对日期；知道提交版本时可补充版本，未提交改动标注“当前工作区”，不冒充已发布版本。

将来源登记在总文档的追溯表中，以来源编号供需求、页面及验收引用。来源说明保留必要摘要，避免复制私密原文。需要附带用户材料或截图时，使用用户允许保存的内容与位置。

更新按“规则 → 受影响字段/操作/状态 → 权限与相关页面 → 验收场景”检查。共享规则只保留一个定义位置；页面通过相对链接和编号引用。局部修改保留无关内容、编号及尚未解决的问题。

需求编号在模块内唯一并保持稳定；表格换行、重排或修改文字不生成新编号。新增规则追加编号，拆分规则保留原编号的去向说明。实质性变更记入总文档变更记录，纯排版调整不虚增业务版本。

## 交付检查

- 页面入口、角色、字段、操作、子表和输出在文档中可找到，不仅描述截图中静态可见部分。
- 每个关键操作说明谁能操作、何时可用、前置校验和成功后变化；有依据的失败、撤回、退回、锁定等分支也有说明。
- 时间字段写明是计划期限还是实际事件时间，来源是手工填写还是状态流转记录；未知的到期、重开或重复提交行为列为待确认，不能自造规则。
- 验收采用“前置条件—操作—预期结果”，与需求编号对应，覆盖正常、异常和权限边界；建议性规则的场景标注待确认，不计入已确认验收标准。
- 原型差异集中列出并链接受影响页面，不能把不一致悄悄改写成“双方都正确”。未能核验的部分明确标注。
- 检查相对链接、编号引用、术语一致性以及模板提示是否已替换。总文档能导航到页面，页面能返回总文档。
- 文档任务只检查文档和相关证据，不为此自动执行完整应用构建、修改业务代码或操作外部任务系统。

## 场景复核

生成或维护本技能时，用下列场景检验指引是否能产生正确文档；不要把这些示例直接当成其他模块的业务规则。

| 场景 | 应得结果 | 应避免的结果 |
| --- | --- | --- |
| 已有原型，用户要求补完整需求，但部分边界未知 | 先写有依据的模块总文档及页面明细，未知事项集中登记 | 阻塞所有写作、重复询问已有结论，或默认全部代码行为已获确认 |
| 用户已确认发布时自动记录报名开始时间，代码仍允许手工填日期 | 将自动记录写为目标需求，旧实现列为差异，补对应验收场景 | 为迁就代码把已确认目标改回手工填写，或自行修改代码 |
| 用户只明确报名开始应自动记录，并说其他日期“也类似”；助手建议保留计划截止日期 | 明确已确认部分，其余日期含义及计划字段保留为待确认 | 将助手完整日期方案视为用户已确认 |
| 原型用浏览器存储，演示人员可切换身份，附件有临时容量限制 | 列为演示限制，正式权限和容量要求按已有依据或待确认处理 | 写成生产系统只能本地存储、任意切换角色或必须使用该容量 |
| 已有 REQ、AC 编号，用户只修改一个操作权限 | 原位修改受影响规则和验收，更新引用及变更记录，保留其他编号 | 重建整套文档、全量重编号、顺便发布到任务系统 |
