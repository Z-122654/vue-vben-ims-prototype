# IMS 原型设计

在本仓库中制作便于映射到正式 IMS 系统的业务原型。以下默认值来自用户确认的页面调整，并以 `web-innovation` 当前实现为参考；用户的新要求优先。

编写或维护详细业务需求文档由 [ims-requirements-doc](../ims-requirements-doc/SKILL.md) 负责；本技能聚焦页面布局、组件表现和交互设计，不要求两个技能强制串行调用。

## 工作方式

1. 阅读仓库及目标 app 的 `AGENTS.md`、`CONTEXT.md`，确认本次是方案、调研还是实现。用户只要求讨论时输出方案，不修改业务代码。
2. 梳理主表字段、重复明细、业务状态、操作角色与页面入口；不因为采用某种布局而增加审批、评分或权限规则。
3. 规划或检查页面时阅读 [页面设计约定](references/page-patterns.md)。实现时按 [组件与源码索引](references/implementation-map.md) 查找相近页面，核对实际组件接口后复用。
4. 沿用目标 app 的技术和 Mock 方式。IMS 是设计及交互参照，不直接搬入正式项目的元数据 CRUD 框架。遇到正式 IMS 能否承载某种设计的问题，先查对应源码再下结论。

## 已确认的设计默认值

- **列表**：筛选区 → 操作栏 → 带边框表格 → 数量及分页。查询与重置成组，行操作放在操作列。
- **明细**：使用大尺寸弹窗，保留弹窗标题和顶部操作栏。操作栏不在右侧重复展示业务名称、状态；这些信息作为正文表单字段。
- **面板**：明细中的业务数据项均归属一个具名面板。主表“基本信息”尽量用标签与控件组成的表单展示；正文、联系信息等也归入面板，不散落在标题区或页脚。
- **页签**：需要时在操作栏下用业务页签组织内容，每个页签内仍采用面板。普通分区使用面板，不为每个分区增加页签。
- **子表**：一对多或可增删的重复明细以 IMS 风格表格展示，支持必要的行内编辑和操作。布局调整不擅自改变已有数据存储结构。
- **同源页面**：申报、查看、审核、评审复用基本信息与附件结构，用只读模式和额外业务面板表达区别，不重做另一套摘要布局。
- **视觉**：白底、蓝色操作按钮、蓝色竖线分区标题、细分隔线、浅灰表头和清晰边框；优先复用现有样式与组件。
- **按钮禁用**：沿用 IMS 的灰底灰字效果，文字与图标同步置灰，交互状态不恢复为可用配色；链接和文本按钮保持透明背景。具体色值及验证要求见页面设计约定的“按钮禁用状态”。

## 业务边界

本仓库按 app 组织模块原型，不把所有业务都放进一个泛称 IMS 的新 app。新建 app 或移动共享组件必须有实际需求，普通页面调整不扩大范围。

竞赛模块的六项项目资料、无部门初审、活动级专家名单、开启评审后锁定、暂不汇总评分、手工登记奖项、附件数量与大小限制，都属于该模块需求，**不是所有 IMS 原型的规则**。改该模块时以 `apps/web-innovation/CONTEXT.md` 和现有实现为依据；其他模块另行确定。

区分业务配置与生命周期状态，区分填报人、负责人、处理人等身份。调整字段时检查列表、导出、审核、评审和展示等实际使用点。界面重排不清空旧演示数据；新增字段采用保留既有标识和数据的兼容补齐。

## 验证与交付

- 按目标 app 要求完成类型检查；修改业务逻辑或弹窗公共行为时运行相关测试。纯技能或文档修改只校验文档、路径和配置。
- UI 改动在浏览器检查面板、表单、表格布局，以及只读/可编辑状态、长文本和滚动；按改动范围检查弹窗返回、未保存提醒、刷新保留和旧数据。
- 核对主表数据有面板归属、操作栏无重复业务标题状态、子表没有变成重复表单卡片、同一字段在相关页面含义一致。
- 交付说明实际改动和已执行的验证。未验证的行为如实说明，不把视觉调整描述成真实后端或数据库功能。
