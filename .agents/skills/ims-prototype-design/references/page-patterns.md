# IMS 页面设计约定

以下是本项目默认设计方式，不固定每个业务的字段、审批节点或状态。按实际需求采用相关部分。

## 列表

- 顶部“筛选条件”面板采用对齐的多列表单，查询、重置位于筛选区右侧；允许折叠以增加表格空间。
- 新增、导出、刷新等操作放在表格上方，只展示当前场景需要的操作。
- 表格采用浅灰表头、网格边框和紧凑行距；操作列放明细及允许的行操作，状态可用标签。
- 现有 `ImsTable` 支持列筛选、排序和分页，按需要使用，不要求每一列都增加筛选框。
- 长名称通过合理列宽、换行或可查看完整内容的截断处理；避免挤占操作列。数据量少的编辑子表不必照搬列表分页。
- 从明细返回后保留列表筛选与分页，不通过整页重建模拟刷新。

## 按钮禁用状态

本项目浅色 IMS 业务原型统一采用以下禁用效果，适用于列表操作栏、明细操作栏及子表按钮；不改变业务上何时禁用、何时隐藏按钮的规则。

| 属性 | 普通、主操作及危险按钮 | 链接、文本按钮 |
| --- | --- | --- |
| 背景 | `#dbdee2` | 透明 |
| 文字与图标 | `#c6c8cc` | `#c6c8cc` |
| 边框 | `#d9d9d9` | 透明 |
| 阴影 | 无盒阴影、无文字阴影 | 同左 |
| 鼠标指针 | `not-allowed` | 同左 |

- `hover`、`focus`、`active` 时保持禁用配色，不恢复蓝色或危险操作的红色。启用后恢复该按钮原有样式。
- 使用组件的 `disabled` 属性真正禁用操作，不能只改变颜色或依赖禁用类名；非原生按钮还需阻止点击及键盘激活。图标继承文字颜色，避免单独保留蓝色。
- 使用明确色值，按钮自身保持 `opacity: 1`，不通过整体透明度再次淡化。上述规范仅针对按钮，不覆盖输入框、选择框等控件的禁用样式。
- 蓝色主按钮样式须排除禁用状态，避免覆盖灰色背景。现有 Ant Design Vue 实现同时兼容 `:disabled` 与 `.ant-btn-disabled`，后者仅是样式匹配，不替代禁用行为。
- 浏览器验收应覆盖禁用外观、悬停及点击不生效、启用后恢复；例如子表未选中行时“删除”置灰，选中行后恢复可用，取消选择后再次置灰。链接按钮禁用时仍保持透明背景。

## 明细弹窗与表单

推荐结构：

```text
弹窗标题（如“项目申报明细”）                 关闭图标
操作栏：关闭、保存、刷新、提交等适用操作
可选业务页签
  基本信息面板
    主表字段、业务名称、状态、长文本
  附件或其他子表面板
  当前角色需要的审核/评分等业务面板
```

- 弹窗自身标题描述页面用途，不去掉“活动明细”等标题。操作栏右侧不再放项目名称、活动名称或状态标签。
- 大弹窗内部滚动，尺寸随视口调整。顶部操作栏与正文分开，长表单也能方便操作。
- 基本信息采用标签对齐的表单布局。桌面端参考现有三列网格，长名称可跨两列，简介、正文、成果说明等跨整行；窄屏随网格收缩。
- 编号、状态、自动带出字段及只读页面用只读/禁用控件表达，注意保持可读性。不要为了只读而重新设计成一套卡片或文章排版。
- 每个数据项有面板归属。帮助说明可紧邻字段，页面操作提示不必伪装成业务字段。
- 关闭按钮、右上角关闭和 Esc 使用一致的关闭检查；未保存内容需要提醒。刷新编辑数据也要处理未保存内容。遮罩误点不应丢失编辑。
- 从父明细打开项目、评审等子明细后，关闭子明细应返回父明细及原页签。关闭只放弃未保存编辑，不清除已保存数据。

### 公示明细的参照

“公示标题、组织单位、公示日期、当前状态、公示正文、异议反馈联系人、联系电话”均放在“基本信息”面板的只读表单内。“获奖名单”放在独立面板的表格中。

不要采用居中的文章大标题、标题下散列日期状态、面板外正文和底部联系方式。证书预览等独立输出物可保留证书排版，不当作普通主表明细处理。

## 页签与面板

- 一个业务对象有多个内容集合时可以使用页签，如活动信息、参赛作品、申报审核、专家评审记录、获奖登记与公示；按角色及业务状态展示实际适用项。
- 页签负责切换业务内容，面板负责分组数据。页签里仍使用基本信息、附件或子表等面板。
- 主表内容、关联记录和审核记录可以放在同一弹窗，但页签位置并不决定数据归属、权限或级联保存关系。
- 切换页签或折叠面板不清空编辑数据。隐藏字段是否参与校验按业务语义决定，不能用卸载组件绕过必填校验。

## 子表与关联表格

- 同类重复条目用表格展示。编辑子表在上方放新增、勾选删除等适用按钮；查看型关联列表只保留查看、导出等适用操作。
- 行号只是显示顺序。行记录及关联字段保留稳定 ID，不用显示名、行索引作为持久化关联键。
- 字段控件置于对应单元格内；只开放允许编辑的列。分组状态锁定时同步锁定增删与行内编辑。
- 业务上的一对多结构可先由原型数组或映射存储；表格展示不等于已建数据库子表，也不要求为了布局强制改写原有数据模型。

### 评分页面的参照

| 场景 | 子表列 | 编辑范围 |
| --- | --- | --- |
| 活动评分指标 | 勾选、序号、指标名称、满分 | 按活动状态允许新增、删除和编辑 |
| 专家评分 | 序号、指标名称、满分、评分 | 只有评分列按评审状态可编辑 |

评审意见是该次评审主记录的字段，放在“专家评分”面板内的表单区域，不复制成每个指标的意见列。评分仍按指标 ID 对应；不要因为换成表格自动增加合计、平均分或排名。

## 相关明细复用

- 以申报明细的“基本信息＋附件”为同源页面基础。评审页面沿用相同顺序与字段布局，材料只读，追加“专家评分”面板。
- 审核页需要填报人等补充信息时在相应面板中展示；材料的项目负责人不能被登录人或代填人替代。
- 主表业务状态和审核/评审记录状态分别放在所属面板，不能用一个标签混指两种状态。

## 附件与流程

- 附件独立成面板，以名称、大小、上传时间、上传人和操作等列展示。展示范围等字段仅在业务需要时加入。
- 只读页面保留获准的下载及可用预览，不提供上传、删除或修改展示范围。Word 提供下载查看；无真实预览能力的格式不显示预览按钮。
- 本地原型的上传、保存、重开、刷新及下载应按当前存储方案形成可演示闭环。限制值以模块需求为准，用户真实材料不成为仓库预置数据。
- 流程图使用独立弹窗，展示节点、连线、当前进度和处理记录；节点注明实际角色，记录展示实际处理人、意见与时间。
- 新建、提交、完成不必都是人工审批节点。审批节点来自需求，不能为贴合示意图增加部门初审或领导审批。
- 未发生节点不得显示为已处理；退回、撤回后的当前状态应与历史记录一致。相邻事件的时间差不能冒充真实审批耗时。
