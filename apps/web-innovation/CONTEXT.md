# web-innovation 应用上下文

## 定位

`@vben/web-innovation` 是仓库内独立的 IMS 前端原型应用。当前使用 Vue 3、TypeScript、Vite、Ant Design Vue 和 Vben 共享能力。不接入真实后端；页面和交互所需数据全部使用 Mock，业务流程只模拟状态变化。项目整体背景见 `../../CONTEXT.md`。

## 当前结构

- `src/main.ts`、`src/bootstrap.ts`、`src/app.vue`：应用入口和初始化。
- `src/views/`：当前包含仪表盘、示例以及登录、个人资料等核心页面。
- `src/router/routes/modules/`：功能路由，包含 dashboard、vben 与 competition 模块。
- `src/api/`：请求封装及登录、用户、菜单等接口入口。
- `src/adapter/`：组件、表单与 VXE 表格适配。
- `src/store/`、`src/layouts/`：应用状态与布局。
- `src/locales/`、`src/preferences.ts`：多语言与应用偏好。
- `vite.config.ts`：应用构建与开发代理配置。

本应用与 `web-antd` 拥有各自的源码、路由和启动脚本，当前基础结构相近。应用内使用 `#/` 别名，共享能力使用 `@vben/*`；功能演进以本应用需求为准。

## Mock 方式

- 登录页保留演示账号选择与账号密码校验，取消滑块验证，便于原型测试；登录仍使用本地 Mock。
- 应用默认使用亮色主题；浏览器已保存的手动主题选择继续沿用，可通过顶部主题按钮切换。

### 创新竞赛与成果评比原型

- 功能入口：`/competition/activities`（活动中心）、`/competition/entries`（我的参赛）、`/competition/reviews`（评审工作台）、`/competition/results`（结果公示）。
- 业务实现位于 `src/views/competition/`。`model.ts` 定义类型和状态操作，`seed.ts` 提供虚构数据，`store.ts` 处理本地持久化；页面使用 Ant Design Vue 与应用 VXE 适配器。
- 参考 IMS 的筛选区、操作工具栏、带边框表格、分区明细表单、附件子表和流程弹窗，不接入其他创新业务模块。
- 新增及四类明细统一在大尺寸弹窗中打开，不新增应用页签；内部独立滚动，关闭后保留列表筛选和分页。从活动打开作品或评审等子明细，关闭后返回父弹窗及原页签。关闭按钮、右上角关闭和 Esc 均检查未保存内容；遮罩点击不关闭。旧明细地址兼容重定向到列表并打开相应弹窗。
- 各明细弹窗的操作栏仅放操作按钮，不在右侧重复显示业务标题和状态；名称与状态放在表单正文，公示标题、组织单位、日期、状态、正文及异议反馈联系方式统一放入“基本信息”面板的只读表单中，“获奖名单”保留为独立面板，保留弹窗自身标题。
- 页面顶部可切换虚构演示身份：陈嘉宁（管理员）、林知远／周亦安／许文清（员工）、沈明／顾言（专家）、赵启航（运行部管理员）。这是原型身份切换，不是正式权限系统。
- 不设部门初审；材料审核及补交处理固定由活动发布人负责（SRC-33），保留原组织管理权限。每个员工可申报多个独立作品，开始评审后锁定材料。
- 项目申报采用部门、项目名称、项目负责人、项目类别、项目简介（1000 字以内）、获得成果／专利六项资料及附件；项目类别、成果／专利及申报附件均选填，类别留空、零附件允许保存、首次提交和撤回／退回重提；类别填写时仍限100字（SRC-32）；成果／专利与竞赛获奖等级独立。完整正文、联系方式、团队等资料放在申报书，不再重复填写，活动不再限制个人／团队参赛形式。
- 负责人默认当前用户，仅可另选登录人同部门且未被选为本活动专家的演示人员，部门随负责人带出。新申报唯一入口为活动中心列表操作列“申报”，活动带入只读；管理员／专家可按本部门报名资格兼任填报人，但不能同时作为同一活动所选专家和有效申报的填报人或负责人。`leaderId` 用于项目展示、评审及证书；`ownerId` 始终表示填报人，决定“我的参赛”、编辑、内部材料访问及报名范围。旧记录加载时只补 `leaderId` 和 `achievements`，保留原类别、旧字段、附件和流程数据。
- 项目申报明细对所有获准浏览者统一复用基本信息表单，包含填报人、成果／专利等全部字段；普通浏览者全部只读，仅可查看公开附件，不开放流程图和内部材料。活动参赛作品与公示获奖名单共用此明细，原访问及编辑条件保持不变。
- 专家评审采用“基本信息 → 附件 → 专家评分”的纵向可折叠分区；基本信息与申报明细共用 `EntryInformation.vue`，材料全部只读，附件仅供查看和下载。项目名称与申报状态在基本信息中展示，评审状态在专家评分分区中展示。
- 活动信息中通过 `expertIds` 多选评审专家；草稿可编辑全部配置，报名中仅允许保存专家名单。候选来自全部演示人员，可跨部门且无需预设专家角色；评审专家必填，草稿保存、发布及保存名单均至少选择一位；配置及保存名单时排除本活动待审核、退回修改、审核通过项目的填报人与负责人；草稿、已撤回、已终止不占用身份。申报入口对本活动专家禁用，负责人候选禁用本活动专家；提交／重提再次按最新名单检查，允许原编辑资格下保存冲突草稿。审核通过及开启评审保留最终校验，旧已选冲突可移除，不自动改写项目、评分或名单（SRC-30）。开启时为所有审核通过的项目生成“项目 × 专家”独立任务并锁定名单。原“评审管理”改为“专家评审记录”，不再逐项目分配专家。
- 旧活动缺失专家字段时从已有任务提取名单；仅评审中的活动补齐缺失任务，保留已有评分、意见及历史，重复加载不重复生成。待公示、已公示、已结束及取消活动不追加历史待办。完成评审要求每个项目的所有配置专家均已提交。
- 活动评分指标与专家评分共用 `ScoringTable.vue`，采用带边框的 IMS 子表表格。草稿活动可新增、勾选删除及行内编辑指标；发布后指标只读。专家表格按活动指标展示，只有评分列可编辑，评审意见仍为主记录字段。沿用 `criteria[]` 和按指标 ID 索引的 `scores` 本地数据，行号仅用于展示，不重建 ID、不清空旧评分，也不增加汇总。
- 专家评分独立暂存／提交；不计算总分、平均分、排名，不实现投票和投票计分。管理员可退回已提交评审。
- “参赛作品展示”只控制活动的参赛作品页签及作品浏览，不影响获奖结果公示。预置“设备维护创新成果评比（不展示参赛作品示例）”为关闭展示的已公示活动；旧浏览器仅补充这一示例及关联项目、评分，不覆盖原有数据。
- 获奖名单依据线下确认结果手工登记；全部参评作品的专家任务提交后可进入待公示阶段。允许零获奖公示，正文须说明；公示后锁定普通编辑，管理员填写原因创建独立更正草稿，重新发布保留旧版本，草稿不影响当前公示。带演示标识的 SVG 证书只供该活动授权管理员、填报人及项目负责人预览下载。
- 活动阶段由授权组织范围内管理员手动推进；报名开始、评审开始／完成、活动结束及公示时间在操作成功时自动记录，公示日期取实际发布时间。两个计划截止人工设置，报名中／评审中可在相应阶段填写原因调整。材料全部收口、至少一个审核通过项目且专家校验通过即可提前开启评审，不受报名截止限制；开启立即停止报名及材料修改，保留原计划截止，计划评审逾期只提醒、不阻止提交。退回申报仅按补交截止编辑重提，活动发布人可填原因延期或终止；已终止保留、不参评、不阻塞开启。初始化示例日期相对当日生成，过期后可重置演示数据。
- 数据使用 `vben-web-innovation:competition:v1` 保存到 localStorage，身份使用 `vben-web-innovation:competition:actor`，刷新保留；“重置演示”恢复初始数据。
- `workflow-examples.ts` 补充9个活动、19个项目、22条评审记录，覆盖全部活动／申报／评分状态和报名截止、补交逾期、评审逾期场景；操作入口及身份见 `docs/competition-demo-data.md`。首次载入立即保存日期；已有浏览器按 `demoPacks` 标记增量安装一次，不覆盖已修改记录、不恢复后来删除的示例草稿。日期随后正常推进，刷新不自动延期。
- 附件以 data URL 在本浏览器内保存，单文件上限 1 MB，每条记录最多 6 个；支持文本、图片、PDF 预览及附件下载，Office 文件下载查看。存储不足时提示并阻止本次保存。
- Word 申报书支持 `.doc`、`.docx` 原文件上传和下载，不解析正文或自动回填；仅可预览的文件类型显示预览按钮。用户的实际申报书不进入仓库或预置数据。
- 模块数据无需服务端。应用外壳仍沿用原有本地 Mock 登录；静态构建预览需要配套运行 `apps/backend-mock` 并正确代理 `/api`，不会自动启动开发插件。
- 第1批流程与权限验证及未覆盖范围见 `docs/requirements/competition/validation-batch-1.md`；旧实际时间仅由明确历史事件补齐，保留旧计划日期但不作为实际值，缺失显示“历史未记录”，不重置现有数据。
- 附件公开范围按后续确认调整为填报人在可编辑状态设置并保存生效，无需管理员确认；已移除独立确认入口和审核确认项。旧拟公开选择兼容为公开，未勾选仍为内部，文件及历史保留；公开附件仍受项目浏览权限约束。提交保存负责人姓名部门快照，公示保存不可随目录变化的获奖资料；首次／最近提交时间保留，缺历史不猜测。仅无任何申报的草稿活动、本人从未提交的草稿申报可删除；取消必填原因且保留历史。申报数排除草稿／撤回／终止，通过数单列；名单和评审子表导出当前筛选全部结果。验证及边界见 `docs/requirements/competition/validation-batch-2.md`。
- 第3批统一申报要求、活动取消、获奖及最近退回信息的面板表单，流程图分三区，专家也显示填报人。后续按用户要求移除项目申报的“材料处理信息”面板，驳回处理信息由流程图查看，补交与历史规则保留。保存／提交业务层统一名称、类别、简介长度，指标满分1～100整数，评分最多一位小数；活动类型支持自定义并复用已存候选，尚非独立字典管理。76项测试和7身份页面检查见 `docs/requirements/competition/validation-batch-3.md`；不重置旧资料或改写旧评分。
- 验证：`pnpm --filter @vben/web-innovation run typecheck`；`pnpm exec vitest run apps/web-innovation/src/views/competition`。

开发环境已启用 Nitro Mock 插件，`/api` 代理目标为 `http://localhost:5320/api`。可复用 `../backend-mock/` 的模拟接口，或使用功能模块内的本地 Mock 数据。应用专属模拟数据应与其他应用区分，避免相互覆盖演示状态。构建预览需确保 Mock 数据来源可用，不能依赖开发插件自动启动服务。

## 根目录执行命令

- 开发：`pnpm dev:innovation`

- 预览：`pnpm --filter @vben/web-innovation run preview`

- 一致性复核后（SRC-23）：活动已取消时申报草稿也禁止删除；活动仍为报名中时允许活动发布人将审核通过项目退回补充（含报名截止后），补交重提后再次审核，开启评审后仍禁止退回。历史后续阶段缺专家名单时提示“历史专家信息缺失”，不补造任务。零获奖说明由管理员在正文自行填写，无新增字段或内容强制校验，标题和正文仍必填。我的参赛导出不含退回原因，驳回信息经流程图查看。

- 兼容复核修正（SRC-24）：草稿／退回修改／已撤回展示当前已保存负责人，提交快照只在成功提交时更新，公示及证书继续使用冻结资料。旧最近提交时间仅从明确提交历史恢复，无依据的已提交记录显示历史未记录；专家名单缺失或空数组只从本活动已有任务去重恢复，已有非空名单保持，后续阶段不新增任务。验证见 `docs/requirements/competition/validation-compatibility.md`。

- 发布与历史边界复核（SRC-25）：首次发布与更正发布复用获奖有效性校验，失败不写入发布时间和版本。旧已提交记录的首次时间未知时，重提后仍保留未知；专家首次时间已有值不覆盖。审核列表与专家评审统一显示“历史未记录”，从未提交的评审显示“尚未提交”。奖项设置提示发布必填、草稿可暂不填写；申报驳回信息仍仅经流程入口查看。验证见 `docs/requirements/competition/validation-publication-history.md`。

- 流程及输出复核（SRC-26）：提交节点复用状态与历史判断，缺提交时间仍展示历史未记录，不补造数据。演示证书预览与下载共用 `certificate.ts` 的 SVG，按实际文本行数下移内容及扩展画布；获奖名单 CSV 增加项目类别，共五列，仍按当前筛选全部结果导出。验证见 `docs/requirements/competition/validation-flow-certificate.md`。

- 时间、附件及流程复核（SRC-27）：四项活动实际时间缺失或空字符串时仅据对应历史恢复；附件读取占名额，加入前再查数量并顺序合并，失败释放名额。退回修改高亮填报人提交环节，重提才切回管理员审核，历史保留。验证见 `docs/requirements/competition/validation-time-upload-flow.md`。

- 附件读取衔接（SRC-28）：活动与申报共用读取保护，读取期间禁用保存和提交／发布；关闭、Esc及刷新确认是否取消读取，继续填写保留任务，确认放弃或组件卸载后禁止迟到回写。附件仍选填，旧数据无迁移。验证见 `docs/requirements/competition/validation-attachment-guard.md`。

- 提前开启评审（SRC-29）：取消日期门槛，保留待审核／退回收口、有效专家及本人回避；草稿／撤回／终止不阻止且不参评；成功记录实际开始、锁定名单和材料。验证见 `docs/requirements/competition/validation-early-review.md`。

- 专家与参赛身份前置互斥（SRC-30）：本活动双向检查，跨活动互不影响；冲突信息包含人员、项目及关系。验证见 `docs/requirements/competition/validation-expert-participation.md`。

- 2026-10-28：活动附件新上传仅接受 PDF（扩展名大小写兼容），选择器及读取前校验一致；项目申报附件仍支持 Word 等原格式。原型每文件 1 MB、每条6个限制不变，既有历史附件不清理。活动附件移除展示范围列和公开标记过滤，活动明细可访问者均可查看全部附件；不扩大活动访问或附件编辑权限，项目申报附件公开／内部规则不变（SRC-31）。

- 2026-10-28（SRC-33）：`publisherId`／`publisherName` 在发布活动成功时记录，与结果公示发布人独立；`canProcessEntry` 统一约束材料通过、退回、补交延期和终止。流程图节点显示发布人姓名，其他授权管理员仍可查看内部资料与管理活动。旧数据先据发布历史唯一识别，再按预置活动稳定ID补齐；无依据的自建活动提示历史发布人未记录并禁止四项处理，不重置其他数据，不新增转交或指定界面。
