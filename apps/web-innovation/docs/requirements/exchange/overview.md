# 技术交流研讨详细需求

> 更新日期：2026-11-01；所属应用：web-innovation。
> 状态：首版方案及四项操作细节已确认；已实现本地交流原型，验证记录见 validation-prototype.md。

## 目标与范围

提供日常交流、技术问答、经验分享，形成发布主题、回复讨论、问答采纳、查阅留存的业务闭环。与知识库一起规划，先实现本模块，再实现知识库，最后接通资料引用。

不增加发布前审批、专家派单、即时聊天、在线会议、积分排名、点赞收藏及消息推送。课题内的进展、研讨纪要仍属于课题，不自动同步到交流中心；竞赛专家身份不赋予本模块特殊权限。

## 对象、角色和权限

| 对象／角色 | 定义及可见范围 | 操作与限制 |
| --- | --- | --- |
| 交流主题 | 一条日常交流、技术问答或经验分享；拥有正文和主题附件 | 三种类型共用结构，不建三套重复业务记录 |
| 回复 | 属于一个主题，可引用同主题另一条回复，拥有独立附件 | 单层列表，不做多层嵌套；作者与主题发布人分别记录 |
| 普通员工 | 全体登录员工跨部门查看已发布主题及有效回复 | 可发布本人主题、回复；无专家身份要求 |
| 主题作者 | 本人草稿和本人发布内容 | 编辑草稿、发布；无回复的已发布主题可撤回；问答作者可采纳他人有效答案 |
| 回复作者 | 本人未提交编辑及已提交回复 | 提交后不能直接修改原文，通过追加并引用原回复更正 |
| 交流管理员 | 已发布、已下架主题及管理所需记录 | 有理由下架主题／回复、恢复；不能读取他人的私人主题草稿，不能冒充作者回复 |
| 知识管理员 | 独立的知识整理发布角色 | 不因身份自动获得来源内部资料权限，见共用引用规则 |

普通员工不通过已下架内容的原入口继续浏览或下载。已下架记录供管理员处理，作者可只读本人下架内容及对应下架原因；管理员可查看完整处理记录（EXCHANGE-Q-001）。

| --- | --- | --- |
| EXCHANGE-REQ-001 | 日常交流、技术问答、经验分享使用统一主题模型，按类型筛选 | SRC-E02、E04 |
| EXCHANGE-REQ-002 | 全员跨部门查看已发布主题并回复；未发布草稿只属于作者 | SRC-E02、E04 |
| EXCHANGE-REQ-003 | 草稿保存要求标题，发布要求标题、交流类型、专业分类及正文；发布无需审批 | SRC-E02、E04 |
| EXCHANGE-REQ-004 | 发布后原文只读，通过回复补充；无回复时允许撤回修改；有发布历史不直接删除 | SRC-E02、E04 |
| EXCHANGE-REQ-005 | 单层回复，可引用同主题回复；提交后只读，以追加回复更正，不直接删除正式回复 | SRC-E02、E04 |
| EXCHANGE-REQ-006 | 提问人采纳一条他人有效回复后问题已解决，取消采纳恢复待解决；已解决仍可讨论 | SRC-E02、E04 |
| EXCHANGE-REQ-007 | 管理员下架须原因，保留内容和处理历史；已采纳回复下架须同时取消采纳并恢复待解决 | SRC-E02、E04 |
| EXCHANGE-REQ-008 | 主题和回复附件独立，选填，Word／PDF／图片，随所属记录访问，无逐附件公开开关 | SRC-E02、E04 |
| EXCHANGE-REQ-009 | 首次发布、回复提交及管理操作时间在成功时记录，失败不得部分保存 | SRC-E02；IMS交互规范 |
| EXCHANGE-REQ-010 | 交流内容人工整理为知识，保留来源；采纳不等于正式知识发布 | SRC-E03、E04；[共用引用规则](../knowledge/source-rules.md) |

## 状态与操作

内容状态和问题状态独立。非问答不显示“待解决／已解决”，列表显示“—”。

| 对象／前状态 | 操作／角色 | 前置条件 | 结果及时间 | 异常处理 |
| --- | --- | --- | --- | --- |
| 新建／草稿主题 | 保存／作者 | 标题有效；已填写内容合法 | 草稿，记录更新时间 | 保留输入并定位错误 |
| 草稿主题 | 发布／作者 | 发布必填齐全，附件读取结束 | 已发布；首次发布时间仅首次写入 | 无部分状态和附件保存 |
| 已发布主题 | 撤回／作者 | 无回复；包括下架回复在内均无已提交回复 | 草稿，保留发布历史 | 已产生回复则阻止 |
| 从未发布草稿 | 删除／作者 | 私人草稿且无发布历史 | 删除草稿及从属未发布材料 | 不允许以删除规避历史保留 |
| 已发布主题／有效回复 | 下架／管理员 | 填写原因 | 已下架、记录人员时间；禁止新增互动 | 采纳回复下架时联动清除采纳 |
| 已下架主题／回复 | 恢复／管理员 | 恢复主题不恢复单独下架回复；恢复回复要求父主题已发布 | 恢复有效展示，记录实际操作 | 不补造历史，不自动恢复采纳 |
| 已发布主题 | 回复／员工 | 正文有效，引用同主题有效回复，读取结束 | 生成正式回复，记录作者、提交时间 | 下架后旧弹窗提交拒绝 |
| 待解决问答 | 采纳／主题作者 | 他人有效回复；只允许一条当前采纳 | 已解决，记录采纳时间 | 本人回复、非问答或下架内容拒绝 |
| 已解决问答 | 取消采纳／主题作者 | 仍为当前采纳 | 待解决，保留处理记录 | 不删除答案 |

不设置计划截止日期，不按时间自动变更状态。首次发布与后续修改时间分开；重新发布保留原首次发布时间，另保留实际操作历史。

## 已确认的细节决策

以下建议由用户在2026-11-01确认“未明确的细节就按你的建议”（SRC-E06），编号保留用于追溯。

| 编号 | 事项 | 已确认结论 | 影响 |
| --- | --- | --- | --- |
| EXCHANGE-Q-001 | 作者如何查看本人下架内容，普通用户可看哪些管理原因 | 作者只读本人下架内容及对应下架原因；其他员工不看，管理员查看完整管理记录 | 我的交流、处理记录权限 |
| EXCHANGE-Q-002 | 下架回复是否仍阻止主题撤回，回复数量如何统计 | 任何已提交回复均阻止撤回；普通列表只计有效回复，历史记录保留 | 防止改变他人讨论基础 |
| EXCHANGE-Q-003 | 恢复主题／回复的关联行为 | 恢复主题不批量恢复单独下架回复；父主题下架时禁止单独恢复回复；采纳不自动恢复 | 管理联动 |
| EXCHANGE-Q-004 | 回复是否需独立持久化草稿 | 首版不增加回复草稿列表，编辑弹窗未提交关闭须提醒，提交成功才加入讨论 | 回复保存方式 |

正式文本长度、附件容量／数量、编号格式尚无明确参数；不得直接继承竞赛限额作为正式要求。原型限额在实现时单独说明。

## 原型实现约定

- 使用独立本地存储 `vben-web-innovation:exchange:v1`，刷新保留；身份演示与其他模块独立。重置只影响交流数据。
- 附件临时限制每组6个、单文件1 MB，Word／PDF／PNG／JPG；仅为本浏览器演示容量，不是正式系统要求。正文不另设未经确认的长度上限。
- 保存前读取最新存储，旧弹窗修订号不一致拒绝覆盖；存储失败不更新内存或成功提示。
- 重置示例也使旧弹窗失效，包括先删除再恢复的同标识示例；该行为仅属原型并发保护，不是新增业务流程。
- 交流发布不设审批；处理记录单独入口查看，不增加审批节点或主表下架处理面板。

- 2026-11-01：依知识库SRC-K09接通已发布主题“整理为知识”，保留交流业务状态和作者／回复事实；调用共用来源选择器，不切换任何模块身份。验证见[知识库第2批](../knowledge/validation-batch-2.md)。
