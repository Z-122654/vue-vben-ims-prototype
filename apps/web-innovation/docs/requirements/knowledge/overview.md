# 创新成果知识库详细需求

> 更新日期：2026-11-01；所属应用：web-innovation。
> 状态：既有关键方案及Q-001～003已确认；知识库第1批已实现。第2批来源引用的Q-004～010已确认（SRC-K08），现已按SRC-K09接通三类来源选择、资料带入、多来源关系、复核及源模块快捷入口。

## 目标与边界

统一留存可复用的成果、案例、文档，通过统一检索查阅。原业务记录仍在交流、课题、竞赛模块；知识库保存整理后的正式内容并关联来源，不重复维护原业务流程。与[交流研讨](../exchange/overview.md)一起规划，分步实现。

首版不做Word／PDF自动解析、附件全文搜索、AI摘要、自动入库、推荐算法、独立审批流或跨模块双向同步。用户已确认人工整理发布，不将“采纳答案”“课题结题”“竞赛公示”直接当作知识发布。

## 对象与角色

| 对象／角色 | 定义及权限 |
| --- | --- |
| 知识条目 | 一条整理后的成果、案例或文档，具有独立状态及正文、附件、来源关系 |
| 成果 | 已形成的方案、装置工具、专利、标准等 |
| 案例 | 可借鉴的问题、处理方法、实施效果 |
| 文档 | 独立技术资料，允许手工登记历史文档 |
| 原作者／负责人 | 来自关联业务资料，不因知识整理而改成当前管理员 |
| 整理人／发布人 | 实际整理和发布知识的人员，与来源人员分别记录 |
| 登录员工 | 查阅已发布知识及允许随知识发布的附件；原始来源仍按源权限访问 |
| 知识管理员 | 新增、整理、发布、下架、删除草稿和维护知识；选择来源必须同时拥有源资料访问权 |

交流管理员、课题管理员、竞赛专家不自动等同知识管理员；演示可安排同一虚构人员具备多种角色，但不能合并权限判断。

## 状态和操作

知识内容状态为草稿、已发布、已下架；“来源需复核”是独立提醒，不替代内容状态，不自动产生审核节点。

| 前状态 | 操作／角色 | 成功结果 | 已确认细节引用 |
| --- | --- | --- | --- |
| 无／草稿 | 手工新增、保存／知识管理员 | 草稿；保存整理内容和附件，不影响其他模块 | 仅标题必填；已填分类及附件校验 |
| 草稿／已下架 | 发布／重新发布／知识管理员 | 已发布，记录实际发布人和最近发布时间；首次发布时间仅首次写入 | 按Q-001重新检查全部发布必填 |
| 已发布 | 下架／知识管理员 | 已下架，普通检索不可见，保留资料 | 原因及恢复规则见Q-002 |
| 草稿 | 删除／知识管理员 | 确认后删除整条知识及所属附件、关联记录，不删除源资料；失败保留原记录 | 2026-11-04 用户确认，仅知识管理列表提供入口 |
| 已下架 | 保存修改／知识管理员 | 保持已下架，更新整理人和实际更新时间；员工仍不可见 | 已发布内容必须先下架；无直接修改或绕过校验的恢复操作 |
| 任意关联条目 | 来源变化 | 标记需复核，不自动覆盖／撤销知识 | 具体检测时机属原型实现，不承诺实时服务 |

操作失败不得出现只发布正文未保存附件或只保存来源关系的部分状态。实际时间只在成功动作记录，不从来源发布时间复制为知识发布时间。

## 已确认的细节决策

| 编号 | 事项 | 已确认结论 | 处理阶段 |
| --- | --- | --- | --- |
| KNOWLEDGE-Q-001 | 各类型保存、发布必填；文档是否必须有文件 | 保存仅标题；发布要求标题、类型、专业、摘要，成果／案例要求有效正文；文档至少有效正文或一份文件，避免空条目 | 知识库实施阶段，不影响交流首批 |
| KNOWLEDGE-Q-002 | 已发布内容编辑、下架原因、恢复／重新发布方式 | 原型首版先下架再编辑重新发布，下架需原因并保留操作历史；避免引入完整版本审批系统 | 知识库实施阶段 |
| KNOWLEDGE-Q-003 | 来源文件被撤权后，知识库中的文件如何处理 | 区分随知识发布的独立选定副本与原文件访问；原文件链接立即按源权限拦截，已发布副本由管理员复核处理 | 附件引用实施阶段，不能用源URL暗中绕过权限 |

上述三项建议已由用户2026-11-01统一确认（SRC-K04）。Q-001、Q-002在第1批实现，Q-003随第2批来源引用实现。正式文本长度、文件限额、编号格式、导出格式和部门人员同步规则仍未指定；不引入数据库设计或真实性能指标。

| KNOWLEDGE-Q-008 | “需复核”如何处理完成，是否必须下架才能处理？ | 管理员逐来源处理并留意见、处理人和时间；无须改知识内容时可确认继续保留，清除本次提醒，不变更知识发布时间。需要改正文／附件／关系时沿用先下架再编辑。所有新增带入须重新验证；已有发布资料失效可由管理员说明继续保留或下架，不能把“当前无权访问”冒充“已核对原文”。仍有未处理提醒时阻止重新发布，但不自动下架当前已发布知识 | 复核入口、处理记录、重新发布；不增加审批流程 |
| KNOWLEDGE-Q-009 | 移除来源关系时，已经整理的正文和文件是否一起删除？ | 不自动删除正文或文件副本。按2026-11-04确认，子表勾选批量删除仅移除编辑态关系，随主表保存；材料继续追溯。管理员如需清理材料，在“查看关联记录”中单独发起并确认影响。未首次发布的材料若来源失效，按Q-007处理，不可仅解绑后直接公开。已发布知识调整关系同样须先下架 | 关系维护、附件归属、误删防护与权限边界 |
| KNOWLEDGE-Q-010 | 哪些来源变化触发提醒，何时检查？ | 只检查选定内容、人员事实、选定文件、可用状态及相关采纳／有效公示版本；未选回复新增、无关进展和管理日志变化不提醒。进入知识管理／明细、手动刷新、保存／发布时核对；同一已处理版本不重复提醒，后续变化再提示。无法读取显示“暂无法核对”，不将一次故障或某个人失权认定为来源已删除，不承诺后台实时推送 | 复核准确性、操作时复验、演示可重复性 |

第2批实现约定：来源选择每次处理一个来源对象，可重复追加；列表查询沿用IMS；文件复制失败整次带入不生效，保留原输入。不新增正式文本长度、文件容量或类型字典指标。具体页面见[来源选择](pages/source-picker.md)。

## 第1批原型约定与边界（历史交付记录；后续增量见第2批及迭代记录）

- 数据位于独立本地键 `vben-web-innovation:knowledge:v1`，身份键加 `:actor`。刷新保留，重置只恢复知识库种子，不影响其他模块；修订号保护旧弹窗，存储失败不更新内存。
- 两位虚构知识管理员陈嘉宁、顾言可维护知识库全部条目；其他演示人员仅查阅已发布知识。不因课题／竞赛／交流角色自动获得知识管理权限。
- 手工资料原作者／负责人和原作者部门选填，按资料填写，不默认当前登录人。整理人为最近一次成功保存／发布者，发布人为最近一次成功发布者；重新发布保留首次时间及处理历史。
- 类型相关补充字段选填；成果／案例的统一正文仍按Q-001必填。切换类型不清空此前填写的类型资料，仅展示并检索当前类型字段，避免误删未保存输入。
- 已发布只读；下架原因必填，原因及处理人时间经管理员“处理记录”入口查看。下架保存后保持下架，重新发布重新校验；当时未增加删除或版本审批功能；后续已确认草稿删除，见2026-11-04变更。
- 附件随知识发布向登录员工可见，无逐附件公开范围。原型临时采用Word、PDF、PNG、JPG，每条6个、单文件1 MB，拒绝空文件；正式格式和容量要求另行确定。Word仅下载，PDF／图片支持预览。
- 本批只提供“知识信息、附件资料”页签；不展示尚不可用的“关联来源”、来源复核筛选或“从已有资料整理”按钮。这些仍属于后续已规划功能，并非需求取消。
