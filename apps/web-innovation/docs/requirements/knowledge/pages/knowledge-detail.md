# 知识明细页面

[返回总需求](../overview.md) · [共用引用规则](../source-rules.md)

> 关联 KNOWLEDGE-REQ-002～009；管理员编辑与员工查看同源大尺寸弹窗。

## 页签与面板

| 页签 | 面板 | 归属及权限 |
| --- | --- | --- |
| 知识信息 | 基本信息、知识内容、类型相关信息 | 知识主记录，已发布员工只读 |
| 附件资料 | 附件子表 | 随知识选定发布的资料，不能混入未选源文件 |
| 关联来源 | 来源子表 | 关系记录，不把原模块内部表单直接公开嵌入 |

当前实现“知识信息、附件资料、关联来源”三个页签；第2批增加来源选择与逐条复核，详见本文末尾及[来源选择](source-picker.md)。

标题和状态位于基本信息；操作栏不重复显示业务标题状态。每项业务数据有具名面板，长正文跨整行，内部滚动。

## 字段

| 字段／面板 | 语义类型 | 数据来源／默认 | 编辑与必填 |
| --- | --- | --- | --- |
| 标题／基本信息 | 知识名称 | 手填或来源带入，可整理 | 保存、发布均必填；草稿或已下架时管理员可编辑 |
| 编号／基本信息 | 独立稳定编号 | 系统生成，不复用源编号 | 只读；格式待定 |
| 知识类型、专业分类／基本信息 | 用途分类及技术专业 | 管理员选择；带入分类可修正 | 发布必填，保存可暂缺；草稿或已下架可编辑 |
| 关键词、摘要／基本信息 | 检索词及简要说明 | 人工整理，可参考源简介 | 摘要发布必填、关键词选填；管理员编辑，长度不擅自设值 |
| 原作者／负责人、原作者部门／基本信息 | 原资料人员信息 | 手工登记时初始为空，按资料填写 | 选填，不默认当前登录人 |
| 整理人、发布人／基本信息 | 最近整理及发布人员 | 保存／发布成功带出当前人员 | 只读，不能覆盖原作者身份 |
| 登记方式／基本信息 | 资料最初创建路径 | 手工登记／从已有资料整理 | 只读，后续增加或移除来源不改写最初创建方式 |
| 内容状态、首次／最近发布时间、更新时间／基本信息 | 知识自身生命周期 | 对应成功操作记录；未发生显示尚未保存／发布 | 只读；重新发布保留首次时间，更新最近发布时间，失败不写入时间 |
| 正文、适用场景／知识内容 | 整理后的可复用内容 | 手工录入或选定源内容带入 | 成果／案例发布须正文；文档正文和附件至少有一项；适用场景选填 |
| 成果名称、类型、编号／专利号／类型信息 | 已形成成果描述 | 成果型适用，可从成果清单带入 | 选填，管理员整理；不能将竞赛奖项误作专利编号 |
| 问题描述、处理方法、实施效果／类型信息 | 可借鉴案例内容 | 案例型适用，可从问答整理 | 补充字段选填，不代替统一正文校验；仅案例展示 |

同一来源人员、课题负责人、竞赛项目负责人、知识整理人分别表达，不能统一以当前登录人回填。

## 附件与来源子表

附件列为名称、大小、上传人、上传时间、操作。手工上传和从来源选择须可区分来源事实；Word仅下载，PDF／图片有实际能力才预览。发布校验与副本边界按已确认Q-001、Q-003执行，具体文件格式和容量仍为实现参数，不默认继承竞赛的PDF活动附件规则。

关联来源按交流研讨、课题攻关、创新竞赛三个内部页签分别显示子表，采用对应模块的业务列；关联时间等追溯信息放在“查看关联记录”独立弹窗的展开表单中。关联对象可以是课题成果行、竞赛项目或选定交流内容，不使用标题当作唯一标识。增加来源关系不自动覆盖已整理正文；选择“带入”时明确目标字段，避免覆盖未保存编辑。

来源打开和下载再次检查源权限与有效性；失败提供不可访问提示，仍可查看本人有权访问的正式知识部分，不回退暴露源缓存。按已确认Q-003，选定并确认随知识发布的附件形成独立副本；原文件访问仍校验源权限。

## 操作和验收

操作包括适用的保存草稿、发布、下架、更新、查看来源、关闭、刷新。非管理员没有修改入口。更新和恢复具体机制见Q-002；不额外引入未确认的审核按钮。

未保存正文、来源选择和文件读取均受关闭／刷新提醒保护；读取结束前不得部分发布，失败保留输入。无源访问权限不能通过模拟其他来源标识绕过；原业务数据不被知识保存回写。

| 编号 | 前置条件与操作 | 预期 |
| --- | --- | --- |
| KNOWLEDGE-AC-002 | 管理员整理后发布，员工打开同一条知识 | 同源表单只读，整理人和来源负责人分别正确；发布时间来自知识发布 |
| KNOWLEDGE-AC-003 | 已编辑知识关联第二来源，尝试重复关联 | 保留已整理内容，提示重复，不自动新增同名知识或覆盖原文 |
| KNOWLEDGE-AC-004 | 员工有知识访问权但无原课题权限，查看来源／附件 | 正式知识可读，源内部资料不因关联而开放 |
| KNOWLEDGE-AC-005 | 源内容改变后重新打开知识 | 已发布正文不自动替换，管理员获得复核提示 |

手工登记依据SRC-K01、K02、K04、K05，见[第1批验证](../validation-batch-1.md)；来源引用依据SRC-K08～K10，已实现，见[第2批验证](../validation-batch-2.md)及[持续核对记录](../audit-iterations.md)。

## 本批操作条件

| 操作 | 显示／可用条件 | 成功及失败 |
| --- | --- | --- |
| 保存草稿／保存 | 知识管理员，草稿／已下架，附件读取结束 | 仅标题必填；检查已填分类和附件；保存不改变下架状态，失败保留输入并定位错误 |
| 发布／重新发布 | 同上 | 检查Q-001全部必填和文件，记录当前发布人及实际时间，正文与附件一起成功保存 |
| 下架 | 知识管理员，已发布 | 单独原因表单必填；成功转已下架，员工列表及已打开明细不再提供内容／附件 |
| 处理记录 | 知识管理员，已有历史 | 独立面板表格显示操作、人员、时间和原因；来源复核另记对应模块、来源标识及当次摘要／版本，历史缺失不补造；不形成审批流 |
| 关闭／刷新 | 当前访问者 | 未保存内容／附件读取先提醒，取消则继续编辑，确认放弃则取消读取并阻止迟到回写；返回保留父列表条件和页码 |

保存前复核当前角色和最新修订号。旧弹窗不得覆盖其他管理员已保存或发布的内容；不通过禁用样式替代业务校验。

## 第2批增量：关联来源页签

依据SRC-K06～K09；已实现。原基本信息、知识内容、类型面板及两页签权限不变，已发布资料修改仍须先下架。共用规则以[来源引用](../source-rules.md)为唯一维护位置，Q-004～010见[总需求](../overview.md#第2批细节确认记录)。

“关联来源”页签包含交流研讨、课题攻关、创新竞赛三个内部页签（默认交流研讨），各有独立子表、“新增、删除、刷新”工具栏、分页和空状态；来源复核操作用独立子弹窗的“复核信息”表单，不在主表顶部额外堆放提醒明细或处理原因。以下字段与操作为新增页面设计，涉及Q-004～010的业务边界已确认（SRC-K08），执行结果见[第2批验证](../validation-batch-2.md)。

| 字段／列 | 含义、数据来源与默认 | 编辑及展示规则 |
| --- | --- | --- |
| 来源模块、对象类型 | 交流主题／选定回复、课题／成果行、获奖项目等 | 从选择结果记录，只读；不手工拼接来源地址 |
| 来源编号／名称、父对象名称 | 来源标题、所属主题／课题／活动事实 | 保存必要追溯摘要；普通用户无源权限时隐藏摘要，按已确认Q-006 |
| 来源人员、部门 | 源作者／负责人，回复单独作者 | 不用知识整理人替代；多来源主表署名按Q-005 |
| 选定内容范围 | 所选回复、成果行、正文部分及带入字段说明 | 只关联时也标明对象；修改范围经选择器确认，不默默扩大到所有资料 |
| 关联人、关联时间 | 成功保存关系的实际操作人和时间 | 首次生成只读；刷新、预览、发布不伪造为新的关联事件 |
| 来源版本／引用时点 | 带入时正式版本、选定内容事实及实际记录时间 | 只读，用于复核；缺历史显示未记录，不能补造源版本 |
| 来源可用提示 | 当前人是否可以访问及当前是否符合新引用状态 | 区分无权、暂无法读取、不再符合资格；不根据一次失败判定删除，按已确认Q-010 |
| 复核提示、最近处理人／时间 | 每条来源变化及最近人工核对记录 | 不代替知识状态；完成机制按已确认Q-008；详细意见经处理记录查看 |
| 操作 | 查看来源、补充带入、复核；关联记录及批量删除见下表 | 按下表控制；非管理员不展示修改及管理操作 |

| 操作 | 显示／可用条件 | 成功和失败反馈 |
| --- | --- | --- |
| 新增 | 知识管理员、草稿／已下架；附件读取期间禁用 | 打开固定当前模块的[来源选择弹窗](source-picker.md)，单条选择后直接加入当前编辑态，仅关联、不复制正文附件；随主表保存，不修改原业务记录 |
| 补充带入 | 同上且当前源内容可访问、符合资格 | 对比当前字段与源候选，只变更确认部分；保留其他未保存内容 |
| 删除 | 同上且已勾选当前页记录；附件读取期间禁用 | 先验证权限及全部选定关系，再一次性标记移除并从编辑表格隐藏；保留正文附件和原模块记录，不弹出材料处理选择，主表保存后生效 |
| 查看关联记录 | 当前知识可访问 | 独立弹窗展示当前模块有效及已移除关系、关联时间／范围／版本；管理员按原权限复核，并可在草稿／已下架状态对未清理的移除关系执行“清理遗留材料”，清理前展示字段附件影响并确认 |
| 子表刷新 | 当前知识可访问 | 重新读取来源信息，不撤销编辑态的新增、删除，不代替主表保存 |
| 查看来源 | 当前知识可访问且当前人有源权限 | 打开源只读明细，返回原知识页签；未取得源权限不展示旧原文缓存 |
| 核对来源 | 知识管理员且需要处理变化 | 表单显示来源事实、处理方式、意见；确认继续保留还是下架修改按已确认Q-008；不能把无权访问记录为已核对原文 |

附件资料子表补充“资料来源”列，区分手工上传与选定来源副本；来源名称按Q-006过滤，不泄漏原文件路径。下载仍由知识访问权限控制独立副本；“查看原文件”如提供，另查源权限，不能替换为内部URL直接访问。复制人与入库时间保留为追溯，不覆盖原上传人和原时间。

主表“登记方式”不再把所有记录写成手工登记：保留最初创建方式（手工登记／从已有资料整理），当前关联模块由子表反映，不因后来解绑或增加来源反复改写历史。首次原作者填入、后续追加署名均按Q-005处理。原型临时附件格式／数量只作演示限制，不提升为正式要求。

关闭、刷新、Esc同时保护未保存来源选择、字段编辑及文件复制；确认放弃后取消复制，不迟到写回。保存和发布须按共用权限表重新校验；新增来源校验失败时保留输入并定位来源行。已存在失效草稿怎样继续保存、重新发布如何阻断，分别按已确认Q-007、008执行。

验收：沿用AC-003～007，覆盖同源多次关联、多个来源作者、已发布目标不能直接修改关系、管理员及员工来源显示差异、来源失权时复制和原文件下载拦截、已发布副本不自动消失、处理来源不自动改变发布时间。涉及Q项的预期已确认（SRC-K08），执行结果单列在第2批验证，不混入第1批历史记录。

## 三类子表展示（2026-11-04 用户确认）

| 子表 | 业务列 |
| --- | --- |
| 交流研讨 | 交流编号、交流标题、专业分类、发布人、部门、发布时间、状态、操作 |
| 课题攻关 | 课题编号、课题名称、关联对象（整体结题资料／具体成果名称）、课题类别、负责人、负责部门、结题时间、状态、操作 |
| 创新竞赛 | 申报编号、项目名称、项目类别、所属活动、项目负责人、部门、公示时间、状态、操作 |

业务列读取当前经过权限校验的来源投影；关联时间／关联人、原作者及回复作者、选定范围、来源版本、关系和管理员复核记录放在“查看关联记录”独立弹窗的展开表单中。来源模块由内部页签表达，不重复列出。源业务状态与关系复核状态分别展示。

无源权限或来源失效时继续按Q-006隐藏信息，管理员只看到原允许的历史摘要，未记录的类别和时间显示“—”，不以关联时间代替业务时间。已移除关系仍按原规则保留追溯，清理完成后不阻止发布。查看、补充带入及适用复核保留；移除改由工具栏批量删除，清理遗留材料放入关联记录；关闭子弹窗返回原内部页签，切换不丢失编辑。员工只读与已发布知识只读规则不变。

## 子表选择与批量删除（2026-11-04 用户确认）

- 三类主子表只展示有效关联，第一列为复选框，不再使用行展开列或行内“移除关系”。工具栏仅“新增、删除、刷新”，无导出；移除原蓝色说明。
- 表头全选／取消仅作用于当前页，部分勾选显示半选。翻页、切换来源页签清空勾选；未勾选时删除按钮灰底灰字禁用。只读不开放新增、删除或勾选；附件读取期间禁用新增、删除及选择。
- 删除仅改变父表单编辑态；主表保存失败保留编辑供重试，未保存关闭沿用放弃确认，放弃后恢复已保存关联。正文和附件保留，仍执行既有来源追溯、发布限制及复核校验。
- 子表下方“查看关联记录”包含旧数据已移除关系及本次待保存移除项，复用原标识与移除标记，不迁移数据。普通读者的隐藏规则同主子表，管理复核信息仍限管理员。
- 关闭选择、来源查看、关联记录或复核子弹窗返回原来源页签；关联记录弹窗内部展开只承载追溯信息。
