## 入口与结构

从[两个列表](topic-list.md)打开同一“课题明细”大尺寸弹窗。新增、查看、立项处理、结题处理均复用表单，不另做纯文本详情。顶部只放当前可用操作，名称与状态位于基本信息，不在右侧重复展示。

| 页签 | 面板 | 数据归属与可见性 |
| --- | --- | --- |
| 课题信息 | 基本信息、攻关方案、团队成员、申报附件 | 课题主表、成员子表及申报附件；全部获准访问者可查看正式材料 |
| 任务计划 | 任务计划 | 课题下单层任务表；草稿阶段可预拟，立项后执行 |
| 进展记录 | 进展记录 | 课题下反馈列表；攻关中允许新增，其他状态仅展示已有记录；未提交进展仅作者可见 |
| 结题资料 | 结题基本信息、成果清单、结题附件 | 课题结题资料及成果子表；攻关中负责人可填写，未提交内容仅负责人可见；其他获准人员只查看最近一次正式提交的版本（正文、成果清单和附件） |

所有页签内仍用面板。立项前结题页签可不展示；任务计划为空显示空表格。切换页签不丢失编辑。关闭、Esc、右上角关闭、刷新按一致的未保存检查处理；子弹窗关闭返回原页签。

## 课题字段（首版规则）

业务类型是字段语义，不是数据库类型；未指定的长度和技术存储规则不在此编造。

| 面板／字段 | 含义与类型 | 来源／默认值 | 必填阶段 | 编辑与校验 |
| --- | --- | --- | --- | --- |
| 基本信息／课题名称 | 文本，拟解决问题的名称 | 手填，初始空 | 草稿保存、提交立项 | 草稿／立项退回可改；纯空白视为未填；横跨较宽位置 |
| 基本信息／课题编号 | 唯一业务编号 | 首次成功保存自动生成，编号格式待定 | 自动 | 只读，不因退回重提变化 |
| 基本信息／课题类别 | 分类文本 | 手选，初始空，候选见列表 | 提交立项必填 | 草稿／立项退回可改；自定义类别暂不增加 |
| 基本信息／负责人 | 人员 | 员工默认本人；管理员可指定 | 提交立项 | 立项前按权限修改，负责部门同步带出；跨人代填见 Q-004 |
| 基本信息／负责部门 | 部门 | 随负责人带出 | 提交立项 | 只读；人员无部门时提示补齐人员信息 |
| 基本信息／填报人 | 人员 | 新建时当前登录人 | 自动 | 只读；变更负责人不改变填报人 |
| 基本信息／当前状态 | 课题状态 | 新建草稿，操作成功后变化 | 自动 | 只读，不能下拉直接修改 |
| 基本信息／计划开始、计划完成 | 日期，课题总体安排 | 手填，默认空 | 提交立项 | 清空视为未填；无任务草稿可留空，提交须填写真实日历日期，完成不得早于开始；立项后由管理员说明原因调整，不覆盖实际时间 |
| 基本信息／首次、最近提交时间 | 实际提交事件时间 | 成功提交立项记录 | 自动 | 未发生显示“尚未提交”；重复提交只更新最近值，历史保留 |
| 基本信息／实际立项、实际结题时间 | 实际事件时间 | 立项通过、结题通过记录 | 自动 | 未发生留空，不拿计划日期补值 |
| 攻关方案／问题与背景 | 多行文本，为什么要攻关 | 手填，默认空 | 提交立项 | 跨整行；提交后只读，退回可改 |
| 攻关方案／攻关目标 | 多行文本，预期达到的效果 | 手填，默认空 | 提交立项 | 跨整行；可写可核验目标，不强制金额或收益计算 |
| 攻关方案／实施方案 | 多行文本，拟采用的路线和做法 | 手填，默认空 | 提交立项 | 跨整行；不再重复增加多个意义相同的简介字段 |
| 攻关方案／预期成果 | 多行文本，拟交付的成果 | 手填，默认空 | 选填 | 与结题时实际成果分开，不自动当作已实现收益 |

草稿保存仅要求名称；已有填写内容仍校验合法性。提交时检查上述必填项。团队成员、附件及任务计划可在立项后完善，不因空子表阻止立项；结题条件独立校验。

## 团队与任务子表（已确认，Q-004、Q-005）

| 子表 | 字段、来源与必填 | 权限和校验 |
| --- | --- | --- |
| 团队成员 | 人员必填；部门自动带出；团队角色为负责人／成员；职责说明选填 | 人员不重复，负责人唯一且自动作为成员。负责人在草稿、立项退回、攻关中维护；跨部门可选。待处理、已结题、已终止只读 |
| 任务计划 | 任务名称、责任人、计划开始、计划完成为完整行必填；任务说明选填；任务状态、实际开始、完成时间自动记录 | 新增默认未开始，责任人来自当前团队。负责人管理未完成任务；责任人只操作本人任务开始／完成，不改主表计划；任务日期处于课题总计划内且先后合法 |

负责人可在草稿／立项退回预拟任务，攻关中才提供“开始”“完成”。任务只有未开始、进行中、已完成三种状态，完成须先开始；这两个操作分别记录实际时间。日期到达不自动开始或完成。

移除成员前检查其任务和历史：有未完成任务时先转交；已有反馈或已完成任务时保留历史成员关联，首版不提供会破坏历史的删除。更换课题负责人作为管理变更处理，不能通过删除团队行间接完成；首版立项后不开放更换，按 Q-004 关联页面规则执行。

任务草稿随课题保存；立项后任务计划单独保存，不顺带提交结题资料。已有执行历史或进展关联的任务不允许删除；已完成任务只读。修改未完成任务的责任人或计划日期时记录原因，保留原计划与变更人、时间。总计划缩短后若不覆盖任务计划，应提示冲突并阻止本次保存，不静默截断任务日期（Q-007）。

## 进展记录页签

使用子表显示记录类型、标题、关联任务、填报人、反馈日期、提交时间及明细操作；正式记录对获准查看课题的人可见，草稿仅作者可见。新增与明细打开[进展明细](progress-detail.md)。进展正文不在此重复维护，不把“填写了进展”等同于完成任务。

## 结题字段与成果子表（已确认，Q-008、Q-011）

| 面板／字段 | 含义、来源和默认值 | 必填及编辑规则 |
| --- | --- | --- |
| 结题基本信息／课题名称、负责人、当前状态 | 当前课题只读带出 | 不重复录入 |
| 结题基本信息／目标完成情况 | 手填多行文本，初始空 | 申请结题必填，说明与立项目标的对应关系 |
| 结题基本信息／结题总结 | 手填多行文本，初始空 | 申请结题必填 |
| 结题基本信息／成果与应用说明 | 手填多行文本，初始空 | 申请结题必填；允许如实记录未达到的目标，不强制产生专利或经济效益 |
| 结题基本信息／遗留问题及建议 | 手填多行文本，初始空 | 选填 |
| 结题基本信息／最近申请时间、实际结题时间 | 申请、通过操作自动记录 | 只读；历次申请在流程历史保留 |
| 成果清单 | 一对多；成果名称、成果类型为新增行必填，成果编号／专利号、成果说明选填 | 表格增删改；允许零行，不强制每个课题形成专利或论文。类型建议方案、装置／工具、制度／标准、专利、论文、其他 |
| 结题附件 | 属于本课题的结题材料 | 选填，范围见下文 |

负责人在攻关中保存结题草稿，保存不要求所有必填项齐全；申请结题时要求正文齐全、至少一项任务且全部完成、没有未完成附件读取。待结题锁定团队、任务、进展及结题编辑；通过后只读，退回后恢复攻关中相应编辑能力。处理意见进入流程历史，不在正文增加“驳回处理信息”。

结题退回或撤回后，负责人编辑的是新草稿；管理员及其他获准人员仍只看到最近正式提交的正文、成果清单和附件，保存草稿不更新该版本，重新申请结题成功后才替换。旧演示数据中待结题／已结题资料可确定为正式版；已退回／撤回等可编辑历史若缺少正式快照，不以当前草稿推造，保留原资料供负责人查看，其他人提示历史正式版本未保留，待重新提交后可查看（SRC-008）。

## 操作栏与处理（首版规则）

| 操作 | 可用角色／状态 | 成功结果或失败说明 |
| --- | --- | --- |
| 关闭、刷新 | 全部获准访问者 | 未保存时提醒；只读刷新直接重读；关闭返回原入口 |
| 保存、提交立项 | 本人草稿／立项退回的填报人或负责人，管理员代填按 Q-004 | 保存不推进状态，提交按总文档流转；校验失败定位字段并保留内容 |
| 撤回立项 | 本次提交人，待立项且未处理 | 回到草稿保留历史、填报人归属及首次提交时间；填报人与负责人可继续查看、修改、重提，其他成员不能看该草稿；最新状态不匹配则阻止（SRC-009） |
| 立项通过、退回 | 立项处理人，待立项 | 再校验处理范围和非本人负责；退回需意见 |
| 保存团队／任务计划 | 负责人，攻关中 | 仅保存当前从属数据，校验人员、日期与已执行任务边界 |
| 调整总体计划 | 管理员，攻关中 | 独立处理，需原因，不改实际时间 |
| 新增进展 | 负责人／成员，攻关中，位于进展页签子表栏 | 打开进展子弹窗 |
| 保存结题、申请结题 | 负责人，攻关中，位于结题页签 | 保存仅存结题草稿，申请按任务与正文条件校验 |
| 结题通过、退回 | 结题处理人，待结题 | 非本人负责；通过记实际结题时间，退回需原因 |
| 撤回结题 | 负责人，待结题且未处理 | 回到攻关中，已有申请历史保留 |
| 终止 | 管理员，总文档允许的状态 | 确认并填写原因，保留全部正式资料、锁定后续编辑 |
| 流程图 | 课题授权查看者，权限依据 Q-009 | 展示立项与结题流程、实际处理角色和历史；未发生的节点不冒充已完成 |

不在一个操作栏同时摆出所有按钮，按状态和当前页签显示；字段不全时可在提交动作说明原因，不能仅隐藏按钮让用户找不到原因。最终业务操作再次检查权限和最新状态，已打开的旧弹窗不能绕过终止、提交锁定或角色变化。

## 附件与保存边界

申报附件和结题附件分别归属对应资料，不因位于同一课题就混成一张列表。附件表列名称、大小、上传人、上传时间、操作；不增加公开范围列。上传、删除与所属资料的编辑权限一致；只读只提供下载和实际支持的预览。格式、可见范围、必填及容量见 Q-009，不沿用竞赛活动仅 PDF 的规则。

未保存编辑须覆盖主表、成员、任务和结题各自的修改；保存范围在按钮文案或页签内说明，不能“保存任务”顺带提交主表。附件读取时相应保存／提交暂不可用，关闭或刷新先处理未完成读取，避免关闭后迟到写入。校验失败不得部分改状态或丢附件。

删除本人进展草稿只更新进展及处理历史、版本，不替换其他页签的未保存表单或正在读取的附件；删除后仍按未保存内容提示关闭。操作使用弹窗所持版本检查，其他页面更新后不得借删除操作覆盖旧编辑。

校验失败自动切换到首个错误所在页签、展开所在面板，展示字段或子表行错误并滚动定位；正文和附件保持原样。任务计划、总计划、反馈日期均检查真实日历日期；日期清空不抛出技术异常。处理弹窗的原因及日期错误在当前弹窗定位，团队／任务错误回到主表对应页签（SRC-008）。

总计划调整例外（SRC-009）：缩短总计划导致已有任务超出范围时，仍留在“调整总体计划”弹窗，错误定位相应的计划开始／完成字段，说明冲突任务名称及其日期；保留已输入日期和原因，不自动关闭或切换任务页签，修正后可再次确定。任务计划自身的编辑错误仍定位任务子表行。

RESEARCH-AC-012：管理员代填提交、被退回后由负责人重提并撤回，负责人仍可在我的课题查看、修改及重提；填报人仍可编辑，普通成员及其他管理员无草稿访问权；从未提交草稿不开放给预先指定的负责人。

RESEARCH-AC-014：管理员分别将总计划开始调晚、完成调早至不能覆盖任务范围，弹窗保持打开并显示冲突任务，输入日期和原因保留，课题版本、日期及历史不变；修正后保存成功。验证见[边界验证记录](../validation-boundaries.md)。
