> 文档状态：首版业务方案已确认（11项结论见 SRC-006）；首版原型已实现。未定正式技术参数单独保留。
> 所属应用：web-innovation；整理日期：2026-10-28。
> 本轮依据 SRC-007 完成前端原型；验证证据与边界见 [首版验证记录](validation-prototype.md)。

## 业务目标与范围

已确认：技术创新管理继续包含技术交流研讨、创新课题攻关、创新竞赛与成果评比、创新成果知识库；本期实现创新课题攻关，覆盖课题立项、团队攻关、过程管理。竞赛模块暂维持现有完成度。

本模块围绕一个课题形成“提出问题 → 立项确认 → 团队执行 → 进展反馈 → 结题确认”的闭环。课题用于管理正在解决的问题、任务及实施过程，与竞赛中提交已有成果参加评比的用途区分。

**已确认首版范围（SRC-006）：**员工自主申报；管理员也可登记课题并指定负责人，统一提交立项。先做定向组织团队，公开发布课题、员工组队认领留待后续规划，本期不实现，见 RESEARCH-Q-001。与业主文档中公开认领的范围差异，已确认按上述方式处理。

| 能力 | 首版范围 | 依据与确认情况 |
| --- | --- | --- |
| 课题登记、立项处理 | 主表登记问题、目标、方案及负责人，模拟立项通过和退回 | 已确认，SRC-006，Q-001、Q-002 |
| 团队与任务计划 | 成员子表、任务子表，任务明确责任人和计划日期 | 已确认，SRC-006，Q-004、Q-005 |
| 过程反馈 | 进展记录、问题风险、下一步计划、阶段附件 | 已确认，SRC-006，Q-006 |
| 结题 | 负责人提交结题总结和成果材料，由本模块业务管理员确认 | 已确认，SRC-006，Q-008 |
| 查询、导出、流程查看 | 在业务列表与课题明细提供必要入口 | 已确认，SRC-006，Q-003 |
| 公开招募、多人竞争认领 | 暂缓，不新增认领菜单及认领审批 | 已确认暂缓，SRC-006，Q-001 |
| 在线讨论、会议纪要 | 首版用进展记录及附件保留研讨结论，实时讨论另议 | 已确认首版简化，SRC-006，Q-010 |
| 甘特图、自动催办 | 首版任务表展示计划日期和逾期提示，暂不做甘特图与消息推送 | 已确认首版简化，SRC-006，Q-005 |
| 预算、采购、积分、专家打分 | 首版不增加独立管理功能 | 不纳入首版范围，后续如需另行规划 |

## 对象与角色

以下为业务模型，仅表达业务归属，不代表数据库设计。

| 对象 | 含义与区别 |
| --- | --- |
| 课题 | 主记录；贯穿申报、实施和结题，立项后不另复制一个“攻关项目” |
| 填报人 | 新建记录的人员，保留来源；与课题负责人分别记录 |
| 课题负责人 | 组织团队、维护计划、汇总进展和申请结题的人员 |
| 团队成员 | 参与课题的人员，可跨部门；其权限不等同于负责人 |
| 任务 | 课题下可独立分工的工作项，不是另一条课题，不设置多级子任务 |
| 进展记录 | 归属课题，可关联该课题某个任务；包含正文与阶段附件 |
| 结题资料 | 同一课题的总结、成果及附件；与获奖登记、知识库记录不同 |
| 处理历史 | 提交、通过、退回、终止等实际操作记录，通过流程入口查看 |

角色与数据范围已确认（Q-002～Q-004，SRC-006），不能套用竞赛模块“活动发布人审核”规则：

| 角色 | 可见范围 | 可执行操作 | 主要限制 |
| --- | --- | --- | --- |
| 业务管理员 | 本模块非草稿课题及本人创建的草稿；撤回草稿按填报人／负责人范围 | 登记课题、立项处理、结题处理、计划调整、终止、查询导出 | 本模块业务管理员单级处理，不允许处理本人负责课题 |
| 课题负责人 | 本人负责的课题及内部材料 | 维护申报、团队与计划，记录进展，申请结题 | 提交待处理时锁定相应表单；不可自行审批 |
| 团队成员 | 本人参与的课题及内部材料 | 查看课题，反馈本人任务，新增进展 | 不修改主表、他人任务或他人进展，不代负责人申请结题 |
| 填报人 | 本人填报的课题 | 提交前维护本人草稿；提交后可查看 | 与负责人不同的代填仅允许管理员操作，Q-004 |
| 其他员工 | 本人草稿；不自动开放他人课题 | 新建本人负责的申报 | 不因同部门或具有竞赛专家身份获得课题访问权 |

管理员兼任负责人时，由另一位有权限的管理员完成立项和结题处理；没有可用处理人时明确提示，不允许自审（Q-002）。首版不设部门初审、专家评分或上级领导审批。

## 业务流程与状态（已确认方案）

主流程：草稿 → 待立项 → 攻关中 → 待结题 → 已结题。

退回分支：待立项 → 立项退回 → 再次提交；待结题 → 攻关中 → 补充后再次申请结题。结题退回不另造“材料处理信息”面板，原因经流程查看。

| 关联需求 | 前状态 | 操作／角色 | 前置条件 | 后状态及实际记录 | 失败或例外 |
| --- | --- | --- | --- | --- | --- |
| REQ-004 | 无／草稿／立项退回 | 保存／填报人或负责人按权限 | 至少填写课题名称，满足已填写字段的基本格式 | 保持草稿或立项退回；记录更新人和时间 | 不因保存而自动立项 |
| REQ-004 | 草稿／立项退回 | 提交立项／负责人或获准代填的管理员 | 完整申报字段、有效负责人、有效计划日期 | 待立项；分别保留首次和最近提交时间 | 校验失败保留输入、不写时间 |
| REQ-004 | 待立项 | 通过／立项处理人 | 当前处理权限有效，非本人负责课题 | 攻关中；记录实际立项时间 | 由本模块有管理权限且非课题负责人的管理员办理 |
| REQ-004 | 待立项 | 退回／立项处理人 | 填写原因 | 立项退回；保留意见、处理人和时间 | 原记录保留，不另建课题 |
| REQ-004 | 待立项 | 撤回／提交人 | 尚未处理 | 草稿；保留已有提交历史 | 已被处理时阻止；重新提交不覆盖首次时间 |
| REQ-005、REQ-006 | 攻关中 | 维护计划、反馈进展／相应角色 | 只处理本课题授权数据 | 状态不变；任务独立记录实际开始、完成时间 | 主表状态不随单项任务完成自动结题 |
| REQ-008 | 攻关中 | 申请结题／负责人 | 任务全部完成，结题总结及成果说明完整 | 待结题；记录本次申请时间，锁定团队、任务、进展及结题材料修改 | 未完成任务列明；零任务不允许申请结题（Q-005） |
| REQ-008 | 待结题 | 通过／结题处理人 | 权限有效，非本人负责课题 | 已结题；记录实际结题时间 | 不自动生成竞赛项目或知识库条目 |
| REQ-008 | 待结题 | 退回／结题处理人，或撤回／负责人 | 退回需原因；撤回限尚未处理 | 攻关中；保留此前申请及处理历史 | 重新申请记录新一次时间，历史不覆盖 |
| REQ-011 | 待立项／立项退回／攻关中／待结题 | 终止／业务管理员 | 填写原因并确认 | 已终止；记录终止人和时间，资料只读 | 已结题不允许直接终止；首版不提供重开 |

表中 REQ 为 `RESEARCH-REQ-` 的简写。只允许删除从未提交过的草稿；其他记录保留历史，不用删除代替终止。保存、提交或处理失败均不应留下部分状态、时间或附件变更。

兼容补充（SRC-011）：旧草稿的首次提交时间缺失时，已有提交时间或“提交立项”历史仍作为曾经提交的依据，不开放删除。本次不迁移时间字段；列表入口与实际删除校验使用同一判断。

计划开始／完成日期属于安排；实际立项时间、任务实际开始／完成时间、实际结题时间属于事件记录。**立项通过不等于团队实际开始施工，不增造“课题实际开工时间”。**任务完成量可统计为“完成任务数／总数”，不直接解释为课题完成百分比；没有任务时显示“尚未制定计划”。

## 原型现状与演示边界

已创建课题管理与审核、我的课题两个菜单及同源课题明细、进展明细、流程弹窗。首版支持立项、团队与任务、进展、结题及终止，七种课题状态均有虚构示例。业务需求依据仍为 SRC-006 及后续确认；管理员菜单按 SRC-010 更名，不以竞赛规则替代课题规则。

当前原型使用虚构身份、Mock 与本地持久化，仅演示流程和权限，不接入正式后端。不将浏览器存储、演示角色切换、竞赛的 1 MB／6 个附件限制写成正式业务要求；不提前设计真实接口、数据库表或性能指标。预置数据覆盖全部课题状态、跨部门团队、逾期、退回、零附件、只读和终止场景。当前原型临时采用每组6个、单文件1 MB的本地附件限制，CSV 导出与自动课题编号仅作演示；这些不是正式系统参数。课题数据独立存储，重置不影响竞赛。
