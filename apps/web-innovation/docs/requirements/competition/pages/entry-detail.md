## 入口与结构

新申报仅来自活动中心列表操作列“申报”，该按钮只向当前登录人部门在活动参赛范围内且满足报名状态／期限的用户提供；若登录人已被选为该活动专家则禁用并显示原因，直接新建入口同样限制。所属活动由当前行带入且不可改，负责人仅可选当前登录人所在部门且未选为本活动专家的人员。取消“我的参赛新增申报”和活动明细“我要申报”入口；SRC-16 已移除这些入口，见 D-11。

已有申报仍可从我的参赛明细、活动申报审核／参赛作品、公示获奖名单项目明细进入，按权限查看、编辑或重提。“唯一入口”限制新建申报，不要求退回修改或草稿重提再创建一条记录。使用同一项目记录的大尺寸弹窗，不复制为另一个业务对象。

| 面板／附属视图 | 数据归属 | 展示条件 |
| --- | --- | --- |
| 基本信息 | 项目申报主资料及所属活动引用 | 所有获准查看该项目的人员统一使用表单；普通浏览者全部只读，SRC-14 |
| 附件 | 该条申报的附件子表 | 内部读者查看全部；填报人可编辑时可增删及设置公开范围，随申报保存生效，无需管理员确认 |
| 获奖结果 | 本项目已公示的奖项与公示入口 | 内部读者，已获奖且活动已公示／结束 |
| 公开附件 | 该条申报中设置为公开的附件 | 非内部读者满足作品展示或已公示获奖条件时；不展示内部附件 |
| 流程图 | 本条申报的材料审核阶段与操作记录 | 已保存且内部读者；作为子弹窗 |
| 审核通过／退回补充弹窗 | 本次材料审核意见和补交期限 | 活动发布人且有原组织管理权限、活动报名中；通过限待审核，退回可用于待审核或审核通过项目 |

项目负责人仅是一项资料，不能单独视为内部读者。完整材料与公开查看的边界见下文；专家评审复用本页基本信息和附件，增加[专家评分面板](review-detail.md)。

## 基本信息字段

### 资料、来源、必填与默认

| 字段 | 业务类型与含义 | 来源／默认 | 保存与提交条件 |
| --- | --- | --- | --- |

| 申报编号 | 自动标识文本 | 新建自动生成 | 只读；编号沿用 IMS，具体配置见 DEP-02 |

| 项目负责人 | IMS 人员引用 | 默认当前登录人；仅可另选当前登录人所在部门人员 | 提交必填且有效；草稿可先未完善；搜索与选择都限制本部门；本活动专家选项禁用并标注原因，SRC-13、SRC-30 |

| 项目类别 | 单个类别文本 | 预置项选择或自定义输入，初始空 | 选填；保存、首次提交及撤回／退回重提均可为空；不是多选标签（SRC-32） |
| 项目简介 | 多行文本，简要介绍项目 | 手填，初始空 | 提交必填；保存和提交都不得超过1000字；独占一行 |
| 获得成果／专利 | 多行文本，已有成果名称、鉴定编号、专利等 | 手填，初始空 | 选填，可为空提交；独占一行；与竞赛奖项独立 |
| 当前状态／申报状态 | 申报生命周期状态 | 初始草稿，随操作变化 | 只读；不能直接改变状态 |
| 最近提交时间 | 最近一次成功提交的实际时间 | 每次成功提交更新，撤回／退回不清空；旧空值仅从明确的“提交申报”历史恢复最近一次时间，已有非空值保留 | 只读；从未提交显示“尚未提交”；已提交过但无可追溯时间显示“历史未记录”，不使用保存、撤回或审核时间替代（SRC-24） |
| 首次提交时间 | 首次成功提交的实际时间 | 仅从未提交的记录首次成功提交时写入；重提保留已有值 | 只读；历史无法追溯时显示“尚未记录”，旧撤回／退回记录重提也不以本次时间冒充首次时间；保存、重提及刷新均保留未知值（SRC-25） |
| 填报人 | 记录创建员工引用 | 创建时固定当前用户 | 所有获准查看项目申报明细的人员均可见，只读；不能改为项目负责人 |
| 申报要求 | 所属活动说明引用 | 来自活动配置 | 基本信息面板中的只读多行表单项，不再次填写；申报和专家评审复用 |

预置类别：生产制造、科技研发、管理创新、五小成果、青年创新创效项目；允许输入其他类别。没有单独青年项目标记。

取消联系方式、个人／团队、团队名称、成员、实施背景、主要做法、创新点、效果与效益的重复表单项；完整材料在申报书中提交。这些旧字段保留旧数据但不影响新表单校验，不因未填写阻止提交。后台竞赛获奖等级和依据不随申报表单保存被覆盖。

### 编辑与校验

| 事项 | 已确认规则／原型现状 | 异常处理 |
| --- | --- | --- |
| 编辑资格 | 填报人本人、活动报名中；草稿／已撤回按普通报名资格，退回修改仅按专属补交期限。现不限制演示身份，按所属记录判定 | 不可编辑时只读且隐藏保存、提交；不能通过更换负责人绕过 |
| 报名范围 | 已确认按当前登录人所在部门匹配活动参赛范围；当前登录人是新记录填报人 | 范围外不提供行申报按钮，直接入口／篡改活动也不能取得资格；退回记录按专属补交期限，仍须本人、活动报名中及有效人员，不新增或转移申报资格 |
| 项目名称 | 必填，最多200字；控件和保存／提交业务层同时校验 | 空白或超长不能保存，不修改原数据（COMP-Q-010） |
| 项目类别 | 选填的单个类别；自定义与预置等价，填写时最多100字 | 留空不阻止保存或提交；控件和保存／提交业务层仍限制长度（SRC-32） |
| 简介 | 已确认最多1000字，提交不能仅空白 | 超长保存和提交均失败；缺简介仅阻止提交 |
| 负责人及部门 | 有效人员且属于当前登录人所在部门，部门自动带出；更换本部门负责人不改变填报归属 | 跨部门人员不出现在选项中；非法传入跨部门负责人须拦截，不因活动包含多个部门而放宽 |
| 专家身份互斥 | 提交及重提按最新活动名单检查填报人和项目负责人，任一冲突均阻止；符合原编辑条件仍可保存资料 | 显示冲突人员、项目、关系和处理建议；不能更换负责人绕过填报人冲突，不自动清空资料。草稿、撤回、终止不阻止管理员将相关人员选为专家（SRC-30） |
| 附件 | 选填，保存及提交均允许零附件；已有成果／专利仍可空 | SRC-20 调整为非必填；已上传文件仍遵循格式、大小、数量及访问权限规则，不自动判断 Word 正文是否完整 |
| 记录所属关系 | 所属活动自行申报入口带入后即固定，填报人固定当前用户 | 非法变更阻止保存，保持原记录；无活动上下文不能独立新建 |

已确认普通报名从活动成功发布后开放，报名截止当天允许，之后停止新申报；管理员在报名中调整截止并留痕后，以最新期限判断。实际报名开始只读，不能由填报人调整。退回修改仅按补交截止，截止当天可补交，普通报名尚未截止也不能覆盖已过期补交期限；主动撤回只限普通报名期，撤回后按普通期限重提。本批已按 COMP-Q-003 实现（SRC-16）。

新建弹窗现只读带入活动，负责人仅选本部门；业务保存再次校验，不能篡改原记录活动和填报人。既有申报及历史负责人资料不因本轮实现自动重写；历史人员／部门口径仍见 COMP-Q-011。活动进入评审、待公示、已公示、已结束后材料锁定；已取消也不允许编辑。期限不足时如何收口见 COMP-Q-003。

## 附件子表与访问

附件归属于单条申报，不能因同一填报人或同一活动而混用。当前活动附件与申报附件采用同样表格表现，但业务归属独立。

| 列／属性 | 类型与来源 | 编辑或显示规则 |
| --- | --- | --- |
| 附件名称 | 原文件名称文本 | 上传自动带入，下载保持原文件名称和内容 |
| 附件大小 | 文件字节数，界面转KB | 自动带入，只读，不按演示显示KB推定正式计量规则 |
| 上传时间 | 选择文件成功读取时的事件时间 | 自动记录，只读；不是申报提交时间 |
| 上传人 | 实际上传用户 | 自动记录，代填仍记填报人，不改成项目负责人 |
| 展示范围 | 公开／仅申报与评审，默认后者 | 填报人在可编辑状态直接设置，保存后对具有项目浏览权限的用户生效；默认内部。旧拟公开选择兼容为公开，未勾选仍为内部（SRC-22） |
| 操作 | 预览、下载、移除 | 编辑时可移除；只读时仅按权限查看／下载 |

已确认支持 `.doc`、`.docx` 原文件上传、保存、删除、下载，不自动解析或回填。现有其他允许格式为 `.pdf`、`.png`、`.jpg`、`.jpeg`、`.txt`、`.xls`、`.xlsx`、`.ppt`、`.pptx`。图片、PDF、TXT现状提供预览；Office文件仅下载查看，不能展示无实际预览能力的按钮。

现状每文件≤1 MB、每条记录最多6份是本轮沿用的演示限制。选择文件只加入当前表单，保存或提交后生效；关闭未保存提醒包含附件变更。移除先确认，保存后生效。正在读取的文件也占用附件名额；文件加入表单前再次检查数量，并顺序合并，不能因同时读取完成而覆盖附件或突破6份上限。读取失败释放名额，可重新选择；读取期间变为只读时不再加入。活动附件与申报附件采用同一规则（SRC-27）。 附件读取状态同步到主表单：读取未完成时提示并禁用保存、提交，活动表单同时禁止发布；即使尚无字段改动，关闭或刷新也须确认是否取消读取。选择继续填写保留读取及表单内容；确认放弃时先取消读取再恢复已保存内容，迟到回调不得重新加入附件。读取失败释放名额并解除操作拦截；零附件仍可保存或提交。组件卸载或转为只读时取消未完成读取（SRC-28）。格式不符、超限、读取失败时提示且不加入；存储失败不应显示保存成功或丢失已有记录。正式容量、格式与存储政策见 COMP-Q-008。

| 访问身份 | 基本资料与内部材料 | 公开范围 |
| --- | --- | --- |
| 填报人、该活动授权组织范围内管理员、已分配的评审专家；SRC-34 新增最新已提交公示轮次审批人对参评项目的只读访问 | 可看完整基本信息及全部申报附件；是否可修改仍按上述规则 | 不受公开标记限制；其他组织管理员身份本身不赋予此权限 |

## 材料审核流程图

逻辑节点为“新建申报 → 提交申报 → 管理员材料审核 → 审核完成”。新建与提交的执行人是填报人；实际审批节点只有管理员材料审核，处理人固定为实际发布活动的人，节点下方显示“活动发布人 · 姓名”（SRC-33）；审核完成表示进入参评范围，不是另一位人员审批，不等于评审完成或已获奖。

退回后由原填报人补充，流程图将“提交申报”节点标为当前环节，并提示“等待填报人补充材料／重新提交”；此时不高亮管理员审核。重新提交成功后才将管理员材料审核标为当前环节，保留已有提交及退回记录，不增加审批节点（SRC-27）。撤回展示当前已撤回状态和历史动作，不能仅因图上提交节点曾完成就当成当前待审。提交节点根据当前状态、已有提交时间及提交／退回／撤回等历史判断是否经过，不以提交时间是否填写作为唯一依据；旧已审核通过记录即使缺少提交时间，提交节点仍应显示完成，同时提示“提交时间历史未记录”，不补造时间或历史（SRC-26）。未提交草稿仍为未提交；当前待审及审核完成节点继续依据当前业务状态，流程图不是完整流程引擎。

流程图弹窗采用“基本信息、材料审核流程、处理记录”三个面板；项目名称与当前状态放入基本信息只读表单。历史记录显示动作、处理人、操作时间；查看详情显示意见和距上次动作的时间。该时间差不是实际审批耗时或考核时长。无部门初审或上级领导审批节点。历史留存、时间口径与重复提交参见 COMP-Q-011。

## 补交、历史和表单展示的确认细则

- COMP-REQ-023：项目申报明细不再展示“材料处理信息”面板，退回、延期及终止的处理人、时间、意见通过流程图处理记录查看（SRC-21）。原填报人继续修改同一申报。活动发布人在报名中可将待审核或审核通过项目退回补充，原因和有效补交期限必填；开启评审后禁止退回。已退回记录仅活动发布人且有原组织权限可填原因延长补交期限或终止该申报；终止后只读，不能提交、不能参评。补交期限校验保持，超期不自动终止，也不允许普通报名窗口绕过补交截止。

- COMP-REQ-024、027：附件默认内部，填报人可编辑时设置公开范围并保存后生效，无需管理员确认。撤回、退回、材料审核不自动改变公开选择；普通浏览仍受项目状态和访问条件约束。正式容量和数量以 IMS 已有配置核对为准，保留常用文件格式及 Word 原文件下载，不解析正文、不提供虚假预览；附件随记录保留。
- COMP-REQ-002：业务主表数据归入面板表单；流程驳回处理信息交由流程图查看，不在本页面重复展示。填写指导和校验反馈可用文字放相关面板内或附近。
