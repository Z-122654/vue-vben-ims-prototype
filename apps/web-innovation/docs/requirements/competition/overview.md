## 1. 阅读约定与业务目标

支持管理员组织活动、员工申报项目、管理员审核材料、多位专家独立评审，以及获奖登记、公示和证书查看。模块独立运行，不依赖其他创新管理模块先建项目或成果。

本文区分四类内容：

| 标记 | 含义 | 使用方式 |
| --- | --- | --- |
| 已确认需求 | 用户明确要求或接受的可定位规则 | 作为目标规则；尚未实现时另列差异 |
| 原型现状 | 源码中可核对的当前行为，缺少独立确认依据 | 用于评审，不能自动作为正式系统要求 |
| 待确认建议 | 尚需业务决定的方案 | 集中引用 COMP-Q 编号，不承诺实现 |
| 演示限制 | 本地模拟、虚构身份、临时上传限制等 | 不直接继承为生产约束 |

页面表格中注明“现状”的默认值、限制和按钮条件均属于原型现状；明确标注已确认的部分优先。业务类型只表达文本、日期、人员引用等语义，不规定数据库或接口结构。

### 本期范围

- 活动中心：活动信息、参赛作品、材料审核、专家评审记录、获奖登记与公示。
- 我的参赛：一人多项目、代填、草稿、提交、退回修改、撤回、申报材料及流程记录。
- 评审工作台：活动统一配置专家，每位专家独立逐项评分、暂存、提交及退回重评。
- 结果公示：公示基本信息、获奖名单、项目公开介绍、证书入口。
- 列表查询与导出、明细弹窗、IMS 面板表单与子表展示。

### 不纳入本期

材料申报不做部门初审或上级领导审批；结果公示按 SRC-34 增加多人领导会签。不做专家总分或平均分汇总、自动排名、投票计分；不新增投票流程。取消单独的个人／团队参赛形式配置和相应提交限制。不接入课题管理、成果库、积分、奖金兑现等其他模块。完整申报书由用户上传，不自动解析 Word 或回填表单。

业主方案中的统一身份、知识库、部门初审、评委会终审和跨模块联动不因出现在总体方案中而自动纳入本模块。正式接口、数据库、性能指标、上线架构均不在本次文档中自行定义。

## 2. 术语、数据对象与角色

| 术语／对象 | 含义与关系 | 重要区别 |
| --- | --- | --- |
| 活动 | 一次创新竞赛或成果评比，承载报名范围、时间安排、评分指标、专家名单、奖项与公示信息 | 采用可维护字典，初始创新竞赛、五小成果评比、技能比武 |
| 项目／参赛作品／申报 | 同一申报业务记录在不同页面的称呼；一条记录属于一个活动 | 不是其他模块的立项项目 |
| 填报人 | 创建申报的员工，决定本人记录、编辑、撤回及内部材料访问权限 | 更换负责人不转移填报人或记录归属 |
| 项目负责人 | 项目资料中的责任人员；申报时只能选择当前登录人所在部门人员，默认当前登录人 | 不因被选中而获得该记录的编辑和内部材料权限；不允许跨部门选择负责人 |
| 部门 | 项目负责人的部门；列表、评审、公示、证书相关资料统一取同一负责人信息 | 报名资格按填报人的部门校验 |
| 评分指标 | 活动下的重复明细，每项有稳定标识、名称、满分 | 表格行号不作为评分关联标识 |
| 评审任务 | 一个项目与一位专家的独立评审记录，下有逐指标评分，主记录有意见和状态 | 多位专家的评分不合并 |
| 已有成果／专利 | 申报时已有成果的自由文本 | 与本次竞赛的获奖等级、获奖依据分别保存 |
| 参赛作品展示 | 控制活动中参赛作品的浏览入口 | 不是活动状态，也不控制结果是否公示 |
| 公示 | 当前原型一项活动对应一份公示内容和获奖名单 | 专门更正记录原因、保留旧版本并经完整会签后自动发布，见 COMP-Q-006、COMP-REQ-031 |

### 角色与数据权限

| 角色 | 可见范围与操作 | 限制与依据 |
| --- | --- | --- |
| 参赛员工／填报人 | 浏览已开放活动；在报名范围内创建多项申报；管理本人填报记录和附件 | 已确认按填报人归属；具体期限与撤回边界见 COMP-Q-001、COMP-Q-003 |
| 项目负责人 | 作为申报责任人显示，可与填报人相同或不同 | 已确认不转移记录权限；独立负责人工作台不在本期 |
| 活动管理员／业务管理员 | 在授权组织范围内创建维护活动、配置专家、查看材料、查看提交的评审、退回评审、登记获奖及公示 | 已确认按组织授权限定管理范围，SRC-13；不能仅凭管理员身份管理全部活动；材料审核及补交处理还必须是该活动发布人（SRC-33） |
| 评审专家 | 由业务管理员在活动中从 IMS 人员目录选择，可跨部门，无需预先具有专家角色或资格；查看本人任务及相关内部材料 | 已确认活动级专家名单及锁定；在申报提交和专家配置时提前进行本人项目整体回避，审核通过和开启评审保留最终检查（SRC-30）；仅专家身份不看其他专家评分；兼任公示审批人时按 SRC-34 只读查看，不能代改他人评分 |
| 公示审批人 | 管理员从全部人员跨部门选择；提交后可读本轮公示、全部参评项目内部材料及正式专家评审记录，处理本人待办 | 不新增系统角色；不限制与提交人、填报人、负责人、专家兼任；不授予管理、材料审核、编辑或额外证书下载权限（SRC-34） |
| 普通浏览者 | 通过参赛作品展示或已发布公示查看允许公开的资料 | 指应用内业务用户，不表示互联网匿名访问；公司内已登录且有模块访问权限的用户；证书另按 COMP-Q-009 限制 |

人员来源统一使用 IMS 人员目录，不另建员工资料。同一人员可兼具员工、管理员、活动评审专家等业务身份，各操作分别校验权限。被选为某活动专家不自动获得其他活动的评审或管理权限。管理操作按授权组织范围校验；个人申报仍按填报归属，专家评分仍按活动任务归属，不能因兼任角色绕过限制。上述规则已由 COMP-Q-002 确认（SRC-13），不将原型的互斥演示身份切换作为正式权限机制。

新申报的唯一入口是“活动中心”列表操作列的“申报”按钮。当前登录人部门必须属于活动配置的参赛范围，同时满足报名阶段和期限；不满足部门范围则不提供按钮。进入后所属活动由当前行带入并只读，项目负责人只能从当前登录人所在部门选择。我的参赛只管理已有申报，活动明细不再提供“我要申报”。界面隐藏不能代替资格校验，直接入口或篡改活动／负责人也不能绕过范围；具体接口不在本次文档定义。

### 时间字段口径

| 时间 | 目标／确认情况 | 原型现状 |
| --- | --- | --- |
| 报名开始时间 | 已确认：发布活动成功、草稿转报名中时自动记录；只读，发布前未发生 | 现发布成功时自动记录，只读；旧实际字段缺失或为空字符串时，仅从对应明确操作历史补齐，已有非空时间保留；无对应历史则保持未知，不由计划期限推算（SRC-27） |
| 报名截止日期 | 已确认：管理员设置的计划期限；截止当天允许普通报名，之后停止新申报；报名中可调整，记录原因和历史 | 草稿设置；报名中通过“调整计划截止”填写原因后变更并记录历史 |
| 评审开始时间 | 已确认：管理员成功开启评审时自动记录，可早于计划报名截止（SRC-29）；只读，未开启前为空 | 材料与专家校验全部通过、成功开启才记录，不限制与计划报名截止的先后关系；未开启为空，只读 |
| 计划评审截止日期 | 已确认：管理员设置；评审中可调整并记录原因和历史；超过期限提示逾期，仍允许符合任务权限及状态的专家提交 | 草稿设置；评审中可带原因调整，活动／工作台／评审明细显示逾期提示，不阻止合法提交 |
| 评审完成时间 | 已确认：管理员成功完成评审时自动记录，不由计划评审截止推算 | 成功完成评审时记录独立只读字段；旧记录按明确事件历史补齐 |
| 补交截止 | 退回补充时由活动发布人指定的补交期限；退回记录只按该期限，不与普通报名期限取任一有效，SRC-15 | 只按有效补交期限编辑／重提；延期和终止均需原因，保留历史 |
| 申报／评审提交时间 | 事件时间，非计划日期 | 已保留首次与最近成功提交时间，默认显示最近；退回、撤回及暂存不清空成功提交时间 |
| 公示时间／公示日期 | 已确认：发布公示成功时自动记录实际时间；公示日期取该时间的日期部分，公示列表、明细及证书保持一致，不单独手填 | 发布成功时记录实际时间并取日期，保存公示内容不允许人工覆盖日期 |
| 活动结束时间 | 已确认：管理员成功结束活动时自动记录；只读 | 成功结束活动时记录独立只读字段；旧记录按明确事件历史补齐 |

上述日期结论依据 SRC-12，COMP-Q-001 已解决。到达计划期限只触发相应资格限制或逾期提示，不自动修改活动状态；相应实际时间只在操作成功时记录，操作未执行或失败不能产生实际时间。计划期限变更不能覆盖已发生的实际时间，也不自动解锁材料或专家名单。延期后按最新保存期限判断普通报名资格；补交按专属期限、撤回后按普通报名期限；普通截止后不再允许主动撤回，见已确认 COMP-Q-003。
