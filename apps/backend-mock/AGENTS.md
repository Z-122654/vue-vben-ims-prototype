# backend-mock 开发指南

适用于 `apps/backend-mock/`，同时遵守根目录 `../../AGENTS.md`。修改前阅读本目录 `CONTEXT.md`。

## Mock 服务边界

- 本应用仅为前端原型提供 Mock 数据，不开发真实业务后端。
- 不连接数据库、不转发到真实后端、不调用真实业务系统，不使用生产凭据或真实用户数据。
- 登录、权限、上传和业务提交等接口仅模拟前端所需的行为。
- 复用 Nitro/H3 与现有路由命名方式，不另建服务框架。
- 响应复用 `utils/response.ts`，保持响应结构、分页字段与前端请求封装一致。
- 新增数据使用明确类型和稳定标识；随机数据应保证关键演示场景可重复。
- 查询、分页、排序和增删改应反映请求参数，更新内存数据后保持列表与详情一致。
- 失败、延迟和权限场景应可控，避免不确定的随机失败干扰正常演示。
- 应用专属数据与路由按功能区分；修改共享接口时检查两个前端应用的调用。
- 不将原型需求扩展为生产级基础设施；内存状态的初始化与重置行为写入上下文说明。

## 验证与维护

- 修改接口后检查成功、空数据、参数边界和所需错误响应，并验证对应前端操作。
- 涉及 Nitro 配置或依赖变更时运行 `pnpm --filter @vben/backend-mock run build`。
- 使用根目录的 Vitest 执行适用测试，不引用本应用不存在的测试或类型检查脚本。
- 不提交 `.nitro/`、`.output/` 等生成内容。
- 文档修改仅检查内容与格式；接口约定或启动方式变化时同步更新 `CONTEXT.md`。
